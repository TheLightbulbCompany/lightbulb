# Specific, Floot, Val Town: how each one actually works

Research note, 2026-10-28. Every claim is tagged [P] primary (vendor docs, vendor site, vendor GitHub, YC page), [S] secondary (aggregator, review, HN comment), or [U] unreachable/unverified. All URLs accessed 2026-10-28. Web search + fetch only, no browser.

## 0. The twelve stages, side by side

| Stage | Specific | Floot | Val Town |
|---|---|---|---|
| Intake | Prompt your own agent; `specific init` writes agent instructions [P] | Prompt in Claude/ChatGPT chat via MCP [P] | Prompt agent with plugin/MCP, or Townie in browser [P] |
| Plan | None built in; agent's job | None built in | None built in |
| Scaffold | `specific init` + `specific.hcl`; examples repo [P] | `create_project` MCP tool returns a TS/React app [P] | `vt create` / MCP create val [P] |
| Sandbox edit | Local machine, `specific dev` [P] | Floot's VM; `write_file`, `edit_file`, `apply_patch` [P] | Browser or local via `vt watch` [P] |
| Preview | `specific dev --tunnel` at `https://<sub>.tunnel.spcf.app`; `specific deploy --preview` [P] | `get_preview_url` tokenised link, 7-day expiry [P] | Every save is live; branches exist (undocumented) [P/U] |
| Provision db+auth | `postgres "main" {}` in HCL; app auth NOT provided [P] | `provision_resource` (Postgres, auth, Google/Microsoft) [P] | Per-val SQLite auto; no end-user auth lib [P] |
| Deploy | `specific deploy` [P] | `publish_app` [P] | `vt push` / save [P] |
| Stable URL | Custom domain via `specific domain add` (paid) [P] | `<name>.floot.app` + custom domain (paid) [P] | `<user>--<id>.web.val.run`, custom subdomain free, custom domain paid [P] |
| Change requests | Re-prompt agent, redeploy | Re-prompt, "Publish changes" [P] | Re-prompt, save |
| Versions/rollback | No rollback command; `deployment retry`, dashboard redeploy [P] | `create_checkpoint` + Checkpoint panel; failed publish keeps old live [P] | Auto-versioned on save; History diff + revert [P] |
| Self-test | `specific check`, `specific query` logs/metrics [P] | `typecheck`, `run_tests`, `screenshot_preview`, `get_logs` [P] | Logs in UI; nothing built-in for tests [P/U] |
| Cost metering | Usage-based $/hr; org "Usage" section [P] | Build actions/day, credits, $ hosting allowance, daily pause [P] | Plan limits only (runs/day, wall-clock); no per-app $ [P] |

## 1. Specific (specific.dev)

**In its own words.** "The cloud platform built for coding agents." Define resources in `specific.hcl`, `specific dev` runs the stack locally, `specific deploy` ships. Services on Kubernetes in AWS eu-central-1, Postgres backed by Neon, object storage by Tigris. [P] https://specific.dev

**Important history.** The 15 Oct 2025 Show HN described a different product: backends generated from natural-language specs, code hidden, "auth intentionally excluded in favour of Auth0/Clerk/WorkOS". [S] https://news.ycombinator.com/item?id=45595760. By 2026 the product is an infra CLI; the March 31 2026 changelog says the CLI was "overhauled so an agent can sign in, test locally, and deploy to production on its own". [P] https://specific.dev/changelog

**Builder flow, every command.** [P] https://docs.specific.dev/reference/cli, https://docs.specific.dev/coding-agents, https://docs.specific.dev/installation-and-usage, https://docs.specific.dev/quickstart

1. Install: `curl -fsSL https://specific.dev/install.sh | sh` (self-updating binary; `specific update`). Linux/macOS/WSL.
2. Agent setup: `specific init` (or `specific init --agent claude cursor`). Claude Code: appends to `CLAUDE.md` and adds permissions for `specific docs` and `specific check` in `.claude/settings.local.json`. Codex/other: appends to `AGENTS.md`. Cursor: `.cursor/rules/specific.mdc`. Adds `.specific` and `specific.local` to `.gitignore`.
3. Docs in the binary: `specific docs`, `specific docs services`, `specific docs integrations/nextjs`, `specific docs migrations/supabase`. Docs MCP server (search/page/list only, not deploy): `https://docs.specific.dev/mcp`. Skill file: `https://docs.specific.dev/skill.md`. One-line onboarding prompt: `Help me get started with Specific by following: https://docs.specific.dev/for-ai/onboarding`.
4. Config: one `specific.hcl` with `build "app" { base = "node"  command = "npm run build" }`, `service "web" { build = build.app  command = "npm start"  endpoint { public = true }  env = { PORT = port  DATABASE_URL = postgres.main.url }  dev { command = "npm run dev" }  pre_deploy { command = "npm run db:migrate" } }`, `postgres "main" {}`. Connection details are injected as env vars; no SDK, no `.env`. [P] https://docs.specific.dev/concepts/how-it-works
5. Develop: `specific dev` (flags `-k/--key` isolated env, `--services`, `--tunnel`), `specific exec <service> -- <cmd>`, `specific psql [db]`, `specific check` (validates HCL, exit 1 on error), `specific clean`, `specific reshape <check|start|complete|status|abort>`.
6. Preview/share: `specific dev --tunnel` exposes public services at `https://<subdomain>.tunnel.spcf.app`; `specific deploy --preview` makes an ephemeral environment with copy-on-write Postgres branch, forked object storage, inherited secrets. GitHub integration makes one per PR and comments the URL (optionally gated by a `specific:preview` label). [P] https://docs.specific.dev/guides/previews, https://docs.specific.dev/llms-full.txt
7. Login: `specific login` (browser; prints device code when non-interactive), `specific login --device-code <code>`, `specific login --agent` (registers an unclaimed agent account that can create one project and deploy; deleted after 48 h unless `specific claim --email <e>` then `specific claim --code <c>`). API keys (full/read-only, expiring) for CI since 31 Aug 2026. Dashboard login is WorkOS AuthKit (HTTP 307 from `https://dashboard.specific.dev/login` to `api.workos.com/user_management/authorize?...provider=authkit`). [P]
8. Deploy: `specific deploy` (`--project`, `-e/--environment`, `--secret`, `--config`, `--preview`), `specific status [--previews] [--format json]`, `specific deployment show [id] [--output]`, `specific deployment retry`, `specific query "<sql>" [--db]` (ClickHouse logs/traces, read-only Postgres), `specific project new <name> --org <id>`, `specific domain add <service> <domain> [-e env]` (prints CNAME to `ingress.specific.dev` or A record; Let's Encrypt TLS; removal dashboard-only; one domain per service). [P] https://docs.specific.dev/guides/domains, https://docs.specific.dev/concepts/deployments

**Infrastructure the app gets, whose account.** Postgres (Neon, PITR, Reshape migrations, realtime sync option), S3-compatible object storage (Tigris), vector, Temporal workflows, cron/workers, secrets, staging + preview environments, domains/TLS/CDN. All live on the Specific organization's account, in Specific's AWS. BYOC/on-prem only on Enterprise. [P] https://specific.dev, https://specific.dev/pricing. End-user auth is NOT provided: "use Better Auth, WorkOS, Clerk, or your own". [P] https://specific.dev

**"Internal apps with automatic authentication" = protected environments.** [P] https://docs.specific.dev/guides/protected
- Dashboard toggle "Require sign-in for services" on an environment; toggling redeploys it. Enforced at Specific's edge for "every public endpoint and every domain in the environment", including custom domains. No application code. Scale plan ($299/mo) and above.
- Who gets in: "members of the Specific organization that owns the project", signing in "using the same identity provider as Specific itself" (WorkOS AuthKit, per the redirect above). Non-members are refused. Docs are explicit: "this is not a login for your end users".
- How the app knows the user: every request carries `X-Specific-Token`, an HS256 JWT with claims `sub` (`user_…`), `email` (verified; absent if unverifiable), `host`, `env` (`env_…`), `iat`, `exp` (24 h). Verify with the key from HCL: `env = { SPECIFIC_TOKEN_SECRET = endpoint.default.token_secret }`; key is scoped to one endpoint in one environment. Session cookie `__specific_sess_v2`: "don't parse it". `specific dev` sends no header; `token_secret` resolves to a fixed dev value so you can sign test tokens.
- Adding a teammate: invite via project switcher > Organization settings (changelog 5 Mar 2026) or verify an email domain so anyone who signs up with it auto-joins (dashboard docs; changelog 4 May 2026 "automatic onboarding"). Scale: "SSO-based membership management"; Enterprise: SAML/OIDC. Removing a member blocks new sign-ins; existing 24 h sessions keep working. [P] https://docs.specific.dev/concepts/dashboard, https://specific.dev/changelog, https://specific.dev/pricing
- Not covered: bypass tokens for webhooks/APIs against a protected environment, roles. [U]

**Versions/rollback.** Rolling deploys with health checks; failed migrations abort and roll back; `specific deployment retry` re-runs a failed deploy; dashboard "redeploy" and "promote a tested staging environment" exist. No documented command to roll back to an earlier build. [P] https://docs.specific.dev/concepts/deployments, https://specific.dev/changelog

**Pricing and limits.** Free $0: 3 projects, 0.25 vCPU/512 MB per service, 512 MB DB, 1 GB files, 1-day retention, badge. Pro $25/mo (includes $25 credit): unlimited projects, previews, custom domains, 50 GB DB, 100 GB files, 7-day retention. Scale $299/mo (includes $299 credit): protected environments, SSO membership, 30-day retention, log/metrics export. Enterprise: BYOC, on-prem, SAML/OIDC. Usage: services $0.009/hr (Tiny) to $0.62/hr (2XL); Postgres $0.15 CU-hr ($0.30 with sync), $0.40/GB-mo; object storage $0.03/GB-mo; workflows $0.075 per 1k actions. Local dev free, no account. Startups up to $10k credits. [P] https://specific.dev/pricing

**Open source.** Pricing page: "open-source is coming soon". GitHub org has MIT `plugin` and `replacebase`, plus examples and a Firecracker fork; CLI and platform are not published. [P] https://github.com/specific-dev, https://specific.dev/pricing

**Funding and team.** YC F25, 2 people, Stockholm. Fabian Lindfors (CEO, ex-Stripe tech lead), Iman Radjavi (CTO). Backers named without amounts: YC, 20VC, BLAST, Inception Fund, Florent Venture Partners, Amino Capital, angels. [P] https://www.ycombinator.com/companies/specific, https://specific.dev/about. VCBacked lists $500K pre-seed Dec 2025 [S] https://www.vcbacked.co/company/specific.

**Gaps vs. the twelve stages.** No intake/plan layer. No end-user auth; team auth is $299/mo. No rollback. No share-to-a-person primitive (sharing = org membership or public). Infra lives on Specific's cloud unless Enterprise BYOC, so "customer-owned infrastructure" is absent below Enterprise. Cost is visible only as usage-based billing, not per app.

## 2. Floot (floot.com)

**In its own words.** "Build real apps in Claude and ChatGPT. Get it live in minutes." "No git, no terminal, no build credits." YC: "The app platform inside Claude and ChatGPT." The exact phrase "replaces Git, Vercel, Supabase, Resend, OneSignal" was not found on floot.com, YC, Product Hunt or docs [U]; the self-hosting page lists the same categories as things you must replace on export (auth, storage, email via Resend/SendGrid, realtime, push VAPID keys, cron). [P] https://floot.com, https://www.ycombinator.com/companies/floot, https://floot.com/docs/projects/self-hosting

**Creating an app from a chat.** [P] https://floot.com/docs/integrations/build-from-claude-and-chatgpt, https://github.com/floothq/mcp, https://floot.com/docs/integrations/what-your-ai-can-do
- Claude: Settings > Connectors > add Floot (directory) or custom connector URL `https://mcp.floot.com/mcp` (must end in `/mcp`), OAuth sign-in to floot.com. Team/Enterprise: org Owner enables first. ChatGPT: app directory, enable via `@Floot`, set "Allow all actions" or every call prompts. Cursor: Marketplace, or `npx -y mcp-remote https://mcp.floot.com/mcp`. Any MCP client: Streamable HTTP, leave bearer fields empty. Requires Claude Pro/Max/Team/Enterprise or ChatGPT with connectors.
- Nothing runs on your machine. Tools: `create_project`, `list_projects`, `search`, `fetch`, `update_project_metadata`; `list_files`, `read_file`/`read_files` (with `older_than` to walk history), `search_code`, `write_file`, `edit_file`, `apply_patch`, `rename_file`, `copy_file`, `delete_file`, `add_dependency`/`remove_dependency`, `get_guides`; `provision_resource` (DB, auth, login providers), `list_resources`, `query_database`, `execute_sql`, `pull_database_schema`, `request_external_resource` (secret entered in browser, never in chat); `get_preview_url`, `screenshot_preview`, `navigate_preview`, `get_current_context`, `view_annotation`; `run_code_in_vm`, `run_code_in_browser`, `typecheck`, `run_tests` (Jasmine); `get_logs`; `publish_app`, `unpublish_app`, `get_publish_status`; `create_checkpoint`; `request_user_upload`, `upload_asset`, `generate_image` (only credit-spending tool), `get_job_status`, `cancel_request`.
- Metering: every tool call except `list_projects`, `get_job_status`, `get_publish_status`, `get_preview_url`, `cancel_request`, `unpublish_app` is one "build action". Model tokens come from your Claude/ChatGPT plan. A connected client can read and edit every project on the account.

**Preview.** `get_preview_url` returns a tokenised link; anyone holding it can use the app (not edit); links expire after 7 days, scoped to one project, cannot be revoked individually; "Only allow internal publish" closes all preview links. Writes stream in live. Preview and published app share the same database. [P] https://floot.com/docs/getting-started/editor-and-preview, https://floot.com/docs/integrations/app-sign-in. Owners can also send "development previews": up to 20 recipients at a time, 50/24 h, recipients must verify email. [P] https://floot.com/docs/projects/sharing-your-projects

**Infrastructure, whose account.** TypeScript/React app; managed Postgres 18 on Neon, AWS us-east-1, sleeps after ~1 min idle, no pooler; file storage; transactional email with send log; web + native push; scheduled jobs (paid only: 10 per project, 5-min minimum; 25 pending timers); backend 512 MB to 4 GB; 15-min request limit; 250 MB backend bundle. All on Floot's accounts; BYO Postgres is possible. [P] https://floot.com/docs/platform/database, https://floot.com/docs/platform/reliability-and-limits, https://floot.com/docs/platform/security-and-data

**End-user sign-in.** "Add login" creates sign-up/sign-in/sessions backed by tables in your project DB; first admin is your Floot email with no password (use "Forgot password?"); Google and Microsoft are brokered by Floot ("no OAuth app for you to register and no client secret"); BYO Apple/GitHub/Slack with your own credentials. App users are separate from Floot accounts. Lockout: 5 failures/15 min. Invite-only or domain-restricted sign-up is not documented [U]. [P] https://floot.com/docs/integrations/app-sign-in

**Private publishing and invitees.** [P] https://floot.com/docs/projects/internal-publish, https://floot.com/docs/projects/sharing-your-projects
- Browser only (no MCP tool): Publish > "Internal publish" tab > "Invited users" emails > "Publish internally". App stays at its normal `<name>.floot.app` address and custom domains; search engines told not to index.
- Who can open: anyone with edit access, plus invitees. "Each one signs in with a Floot account on the address you invited, creating one if they do not have it yet." Invitees cannot open the project. If the app also has its own login, users log in twice (Floot gate, then app).
- What the app learns: a permanent Floot account ID and the email (docs say key records on the ID). Exact header/claim name not documented [U].
- Limits: Free 5 invitees account-wide; paid 500 per project, added 50 at a time. Removal cuts backend/data access within ~1 h. "Only allow internal publish" (Project Settings > Advanced) blocks public publishing.
- Collaborators (editors): email must already have a Floot account; owner needs a paid plan; collaborator needs own paid plan to build via their own MCP client; no view-only role.

**Versions/rollback.** `create_checkpoint` labels a restore point; restore in the Checkpoint panel (code only, never data/files/domains). `read_file older_than` walks history. A failed publish leaves the previous version live. No one-click rollback of a publish: restore checkpoint then publish. DB: paid plans get 7-day continuous recovery, restore done by Floot support. Product Hunt reviewers cite "weak rollback". [P] https://floot.com/docs/projects/publishing, https://floot.com/docs/platform/database; [S] https://www.producthunt.com/posts/floot-mcp

**Ownership and export.** "Completely — code, data, and IP." Code: project name > Get Code > Download as ZIP (paid plans; current project, no history) or Folder Sync. No Git sync: "download the zip and push it yourself." DB: gzipped `pg_dump` (`.sql.gz`), 5 exports/day. Self-host: `pnpm install`, `pnpm vite build`, `pnpm tsx server.ts` after replacing every `@floot/*` import and filling `env.json`. Uploaded files are not in the zip. [P] https://floot.com/docs/faqs/code-data-and-exports, https://floot.com/docs/projects/self-hosting

**Pricing.** Free $0: 100 build actions/day, 3,000 credits once, $3 hosting once, 5 projects, 100 MB files, 5 invitees. Pro $25/mo: 1,000 actions/day, 5,000 credits/mo, $10/mo hosting, custom domain (1 free via IONOS), badge removal, Get Code. Power $100/mo: 5,000/day, 15,000 credits, $25 hosting. Action Boost $5 for 5,000. Hosting is a separate balance; a daily hosting limit pauses the app for the day; when hosting credit runs out the app goes offline with no grace period and the `.floot.app` name is released. [P] https://floot.com/en/pricing, https://floot.com/docs/faqs/billing-credits-and-plans, https://floot.com/docs/platform/reliability-and-limits

**Open source.** Only the connector repo `floothq/mcp` (client configs; no license stated). Platform closed. [P] https://github.com/floothq/mcp

**Funding and team.** YC S25, 4 people, San Francisco. Yujian Yao (CEO; ex-Retool staff engineer who rebuilt Retool's runtime, early Asana). Co-founder Edward Look [S]. $500K listed by aggregator [S] https://altss.com/companies/yc/floot. "5 to 600+ paying customers during the batch" from a job listing [S]. Product Hunt #1 of the day 7 Aug 2025; Floot MCP #2 on 24 Sep 2026. [P] https://www.ycombinator.com/companies/floot; [S] https://www.producthunt.com/posts/floot-mcp

**Gaps.** No intake/plan layer beyond the chat. Everything lives on Floot's AWS; export is a one-way zip, not customer-owned infra. Private publish is browser-only and invitee needs a Floot account; no domain allow-list, no SSO. No rollback of a publish. Cost is metered (good) but hosting pause can take an internal tool offline mid-day.

## 3. Val Town (val.town)

**In its own words.** "A collaborative platform for writing, deploying, and running JavaScript and TypeScript code in the cloud" with the mission of "end-user programming". A val is a folder of files; a file can have an HTTP, Cron or Email trigger. [P] https://docs.val.town/vals/, https://www.val.town/about; [S] https://accel.com/news/our-seed-investment-in-val-town-making-programming-accessible-collaborative-and-fun

**Builder flow.** [P] https://docs.val.town/guides/prompting/cli/, https://github.com/val-town/vt, https://docs.val.town/guides/prompting/claude-code/, https://docs.val.town/guides/prompting/mcp/, https://github.com/val-town/plugins
- Agent route (recommended over CLI): `claude plugin install valtown@claude-plugins-official` or `/plugin install valtown@claude-plugins-official`; MCP-only `claude mcp add --transport http --scope user val-town https://api.val.town/v3/mcp`; then `/mcp`, OAuth sign-in. Codex: `codex plugin marketplace add val-town/plugins`. Cursor: `/add-plugin valtown`. Plugin bundles skills (http-endpoints, crons, SQLite, email, OAuth, frontend). MCP tool names are not published; the Access doc names `create_bypass_token` and says an agent can set a val to Restricted.
- CLI: `deno install -grAf jsr:@valtown/vt`; `vt` (login); `vt create <valName> [dir]`, `vt clone [valUri] [dir] [branch]`, `vt remix <fromValUri> [newName]`, `vt pull`, `vt push`, `vt watch`, `vt checkout <branch>`, `vt branch`, `vt list`, `vt delete`, `vt status`, `vt browse`, `vt config`. CLI writes `AGENTS.md` into the folder. MIT, v0.1.43 on GitHub.
- HTTP handler: `export default async function (req: Request): Promise<Response> { ... }` (Hono etc. work). Every save is versioned (starting at 0) and live. Web UI has History (diff + revert), Branches and Pull requests tabs. [P] https://docs.val.town/vals/http/, https://docs.val.town/reference/version-control/, https://docs.val.town/vals/history

**Infrastructure, whose account.** Deno runtime; per-val private SQLite (Turso; 10 MB free, 1 GB paid); per-val blob storage (S3; counts toward same 10 MB/1 GB); cron (15-min minimum free, 1-min paid, 10 crons/val free, 50 paid); email handlers; env vars; 4 GiB worker memory, 1-min wall-clock free / 10-min paid; 80k chars per file, 1,000 files per val. URL pattern observed in the wild: `https://<user>--<id>.web.val.run` (e.g. `wolf--a31361a6105b4f90956214803ce76db5.web.val.run`), custom `*.val.run` subdomains on Free, custom domains on Pro/Business (CNAME `domains.val.run.` or A `75.2.96.173`/`99.83.186.151`, managed at `val.town/settings/domains`). All on Val Town's infrastructure; no BYOC. No end-user auth library; auth is code (docs example checks an `Authorization` header against `Deno.env.get("SECRET")`). [P] https://docs.val.town/std/sqlite/, https://docs.val.town/std/blob/, https://www.val.town/limits, https://docs.val.town/reference/custom-domains/, https://docs.val.town/reference/permissions/

**Restricted app access, in full.** [P] https://docs.val.town/reference/access/, https://docs.val.town/reference/permissions/
- Two independent switches: Code access (Public / Unlisted / Private, who can read source) and App access (Anyone with the URL / Restricted, who can hit the endpoints). Restricted requires an organization-owned val on a Business account; if the org drops to free, restricted vals return HTTP 402.
- Set in val Settings > App access, or by an agent via MCP. No code change.
- Allow-list entries: Val Town users and organizations by handle; email invitations for people without accounts (expire 7 days, max 20 outstanding per val; invitee gets the val only, not org membership); email domains such as `acme.com` (anyone with a verified address, max 10 domains per val).
- Visitor flow: redirected to sign in to Val Town, then back to the val. Session 30 days. Applies on `val.run` URLs and custom domains alike.
- Identity to the app: every request carries a signed `x-val-town-user` header; POST it to `/v3/val/viewer` with the val's project-scoped API token as Bearer to get `id`, `username`, `bio`, `profile image`, `profile URL`. Email and tier are not exposed. Header is ~1 minute short-lived, bound to the val's project ID, absent on bypass-token requests, so treat it as optional.
- Programmatic callers: bypass tokens `vtba_…` in header `X-Val-Town-Access` or `?val_town_access=` (header preferred). Up to 10 per val, shown once, no expiry, revocable, scoped to one val, anonymous (no identity header). Val Town strips the header/param before your code runs. Mixing a bypass token with a Val Town session is rejected. Create in Settings, API, or MCP `create_bypass_token`.

**Small-software workflow for a team.** Create an org (free; Business from $167/mo for Restricted, environment groups, higher limits). Agent creates an org-owned val with an HTTP trigger and SQLite, saves (live instantly), sets App access to Restricted and adds `yourco.com` as an allowed domain. Share the `*.val.run` URL or CNAME a custom domain. Teammates click, sign in to Val Town once, land in the app; the app calls `/v3/val/viewer` to greet them. Zapier/webhooks get a `vtba_` token in `X-Val-Town-Access`. Changes are saved versions; History reverts. Transferring a val between orgs keeps scoped env vars, SQLite, blob and `*.val.run` endpoints. [P] https://docs.val.town/vals/organizations.md, https://www.val.town/pricing

**Pricing and limits.** Free: unlimited public vals (2,500), 0 private, 1-min runs, 15-min cron, 100k runs/day, 3-day logs, email to self only, MCP. Pro $21/mo: 2,000 private vals, 10-min runs, 1-min cron, 1M runs/day, 10 custom domains, $10 Townie credit. Business from $167/mo: 5M runs/day, unlimited domains, $100 Townie credit, team accounts, "Val Town Access" (Restricted), Slack Connect. Enterprise: log export, SOC 2. [P] https://www.val.town/pricing, https://www.val.town/limits

**Open source.** CLI `vt` (MIT), SDK (MIT), plugins (MIT), docs, editor pieces (`vtlsp`, `deno-http-worker`). Runtime/platform not open. [P] https://github.com/val-town

**Funding and team.** Accel led pre-seed (Aug 2022) and seed (announced 10 Apr 2024, amount not stated by Accel); aggregator says $5.5M total [S] https://www.vcbacked.co/company/val-town. Team page lists six: Steve Krouse (CEO), Tom MacWright (CTO), Potluck Mittal (COO), Brent Jackson, Charlie Molthrop, Pete Millspaugh. [P] https://www.val.town/about; [S] https://accel.com/news/our-seed-investment-in-val-town-making-programming-accessible-collaborative-and-fun

**Gaps.** No intake/plan/scaffold beyond "create val". No sandbox separate from prod (every save is live; branches undocumented). No preview URL concept. No end-user auth library. Rollback is manual revert in the UI. No self-test primitive. No per-app cost; limits are per account. Nothing runs on customer infrastructure. Restricted access needs $167/mo and a Val Town login for every viewer.

## 4. Verdict on "only my teammates can open it, with no second login"

None of the three avoids a platform login: Specific requires membership in the Specific org (WorkOS AuthKit sign-in), Val Town requires a Val Town account, Floot requires a Floot account on the invited email. Measured by "fewest steps per teammate and the app knows who they are":

1. **Specific** is closest to document-like sharing for a team that already lives in it: verify the email domain once, every new hire auto-joins, flip "Require sign-in for services", every endpoint and domain is gated, and the app gets a signed JWT with `sub` and verified `email`. Cost: $299/mo and the viewer still signs into Specific.
2. **Val Town** has the richest mechanism (users, orgs, invited emails, email domains, bypass tokens, signed viewer header, custom domains honoured, agent-settable via MCP) at $167/mo, but exposes no email to the app and every viewer needs a Val Town account.
3. **Floot** is cheapest (free for 5 invitees) and is the only one where sharing is per-app rather than per-org, but it is browser-only, invitee-by-invitee, and the invitee must create a Floot account; no domain allow-list, no SSO.
