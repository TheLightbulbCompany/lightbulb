# Cost cuts: S3, DynamoDB, CloudWatch (2026-11-10)

Evidence is from read-only Cost Explorer, CloudWatch metrics, S3 and DynamoDB
describe calls in account 877352799272, us-east-1, for 3-8 Nov 2026. Savings are
**estimates**.

## 1. S3: ~$8.50/day is internet egress from the CDK assets bucket

**Cause.** The S3 line is not storage or requests. It is `DataTransfer-Out-Bytes`
on `GetObject`, 73-98 GB/day from 6 Nov ($6.61-$8.86/day). By stack tag the cost
is `CDKToolkit`, so the bucket is `cdk-hnb659fds-assets-877352799272-us-east-1`.
The objects are the deploy pipeline's `gha-cdk-out/<run>/cdk.out.tgz` (~40 MB).

The repo Actions variables `DEPLOY_RUNNER` and `CI_RUNNER` changed to
`ubuntu-latest` on 2026-11-05 07:48Z. Before that, the deploy jobs ran on one
self-hosted box, and the host cache in `apps/infra/lib/app.ts` served the tarball
from disk. On GitHub-hosted runners the cache never hits. Then each of the 41
`Assets-*` jobs downloads the whole tarball over the internet: ~1.6 GB per run.
`main` had 44 deploy runs on 8 Nov, which gives ~72 GB.

**Fix (this PR).** `apps/infra/scripts/slice-cdkout.mjs` cuts cdk.out into
`base.tgz` (~0.5 MB: manifests, templates, publish scripts) and one
`<assetId>.tgz` per asset. Each asset job downloads two objects: the base, and
its own asset. The publish script gives the asset id. The host-cache path is
unchanged. Locally all 41 jobs got their asset source from base plus slice. The
download is ~60 MB per run instead of ~1.6 GB (about 96% less).

**Saving (estimate).** ~$240/month at the current run rate. Moving deploy jobs
back to a self-hosted runner would also remove it, but that is a runner/minutes
decision for the owner.

## 2. DynamoDB: room lookups read the whole room each call

**Cause.** Nearly all read units come from `lightbulb-prod-messaging`: ~25M
RRU/day at baseline and ~130-140M on 5-6 Nov UTC. Other tables are under 2.1M
(`containers`). Scans are negligible (≤18k/day). Queries are ~456k/day and
average ~45 RRU each, so a query reads ~180 KB. The table holds 1.04M items, 1.5
GB.

The code path is `messaging_repo.get_message_by_id` and `latest_human_message`.
They read the room's whole `MSG#` partition with strong consistency, then search
it in Python. They have ~25 callers: work dispatch (`openclaw_work`), run events,
replies, needs-you email, Temporal activities. The callers repeat for each turn,
and a big room costs thousands of RRU per call. The 5-6 Nov spike shows 3x
Query, 5x BatchGet and 2.7x TransactWrite, the same read units per query. So the
spike is more traffic hitting the same costly reads, not a new loop. Some callers
pass `triggerMessageId or ""`, and that was a full walk that found nothing.

**Fix (not in this PR).** The product is voice now, so these reads will be cut
by deleting the chat-only callers of these lookups, not by tuning the old chat
plane. A paged-lookup change was tried here and then reverted for that reason.
Read the daily `ConsumedReadCapacityUnits` on the messaging table after the
deletions land.

**Saving (estimate).** Most of the ~$100-150/month of messaging-table reads goes
when the chat-only callers go.

## 3. CloudWatch: no runaway; the cost is fixed observability

**Evidence.** For 9 Oct - 8 Nov: custom metrics $40.30 (134 metric-months, rising
to ~196 in November), alarms $25.16 (~250, ~330 in November), dashboards $4.45.
Log ingestion is $2.55/month and log storage is cents. Every product log group
has a retention. The groups with no retention are old API Gateway execution logs
(`/aws/apigateway/2518tsyg1h/prod`, `g5xmlzqtzc/prod`, ~4.3 GB) and per-owner
AgentCore runtime groups that AWS creates. They cost under $0.20/month.

**No code fix in this PR.** The only real cuts need a decision:
- Dev has the full prod alarm set (~165 alarms, ~$15/month). Keep only the
  page-tier alarms in dev?
- Custom-metric identities grew ~45% in a month. A `list-metrics` audit by
  namespace and dimension set would show which emitter added them. That call was
  outside this pass's allowed reads.
- Retention on the old API Gateway and AgentCore log groups is housekeeping
  (cents).

## Total (estimate)

~$240/month from the S3 fix in this PR; the messaging reads go with the chat-plane deletion. CloudWatch stays ~$85/month
until the decisions above are made.
