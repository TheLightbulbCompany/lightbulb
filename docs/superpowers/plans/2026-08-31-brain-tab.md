# Brain tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** The owner can finally see, edit, and add to what their company knows — a browser + editor over the memory-wiki vault the agents already read and write on EFS, as a `teams-brain` panel under the Knowledge group, with Dreams folded in as a tab.

**Architecture:** The vault lives at `/mnt/efs/users/{owner_id}/wiki/main/` (written exclusively by the container-side memory-wiki plugin; the backend has never touched it, and no owner surface can reach it today). We add a thin backend route pair scoped to the `wiki` subtree — the same guard/read/write machinery `workspace_files.py` already uses for agent workspaces, with the repo's two-layer EFS lock on writes — and a frontend panel that reuses `FileTree` + `FileContentViewer` (both already agent-agnostic props components; the file-viewer's editor, dirty-tracking, and Cmd+S come free). Dreams' existing panel body is re-homed as a Brain tab (it talks to the container over gateway RPC and needs no backend). UX preamble (controller's tab notes): owners trust a brain they can audit — show modified times; "that fact is wrong, fix it" = edit in place; drop-zone lands files for the agents.

**Tech Stack:** FastAPI + the existing `Workspace`/`efs_file_lock` machinery; Next.js panel via the teams-panel registry pattern (3 edits, zero new plumbing).

**Spec:** `docs/superpowers/specs/2026-08-28-owner-data-plane-design.md` §4.3 (brain = truth we originate), §5.1 (Knowledge: Brain — Dreams folds in). NOTE a spec erratum found in planning: §4.7's "widen `agent_redaction`/`curator` to brain writes" is wrong — `curator.py` is marketplace-curator resolution and no prose redactor exists anywhere; redaction here is NET-NEW and stays P2 (ledgered, spec fix rides this PR).

## Global Constraints

- Backend paths: every route pins to the `wiki` subtree via `_validate_relative_path` + `_ensure_within_subtree` (copy from `routers/workspace_files.py:18-58`) — `_resolve_user_file` alone pins only to the user root and is NOT sufficient.
- Every EFS write: `MAX_WRITE_SIZE` 10 MB cap, then the two-layer lock (`get_file_lock(key)` + `fcntl.lockf` on a `.lock` sidecar — `core/services/efs_file_lock.py`; the cron-jobs worked example is `config_patcher.py:1072-1147`), then `Workspace._chown_for_access_point` (uid 1000, else the container sees it read-only).
- NEVER write `openclaw.json` or touch its sidecar protocol from this feature.
- The vault dir may not exist yet (plugin hasn't written) — list returns an empty tree, never 404/500; writes create parents.
- Frontend: brand tokens only; `teams-brain` panel key is NEW (never rename existing keys); registry edits follow the 3-edit teams pattern exactly (`TEAMS_LIST_KEYS` + `PANEL_LOADERS` + `CompanyNav` Knowledge section).
- Wiki page content is agent-written text — render as markdown/plaintext, never dangerouslySetInnerHTML.
- Scoped tests per task; full suites ride CI.

### Task 1: Backend — the brain routes

**Files:**

- Modify: `apps/backend/main.py` (mount under `/api/v1/container`, beside the workspace_files include)
- Test: `apps/backend/tests/unit/routers/test_brain.py`

**Interfaces (all Clerk-authed via the standard `AuthContext` dependency, owner-scoped — same auth as `workspace_files.py`):**
- `GET /container/brain/tree` → `{files: [{name, path, type, size, modified_at}...]}` — recursive listing of `wiki/` via `workspace.list_directory` + the `_collect_recursive` pattern; paths returned RELATIVE to `wiki/` (strip the prefix like `_strip_agent_prefix` does). Missing `wiki/` dir → `{files: []}`.
- `GET /container/brain/file?path=…` → `workspace.read_file_info` result for `wiki/{path}` (text/base64/binary shapes as-is), 404 when absent.
- `PUT /container/brain/file` body `{path, content}` → size-capped, guarded, two-layer-locked write of `wiki/{path}` (create parents; sidecar `wiki/.brain.lock` per file? NO — one sidecar per FILE beside it, `{file}.lock`, matching the cron-jobs example's one-lock-per-data-file shape), then chown; returns the new `{size, modified_at}`.
- `DELETE /container/brain/file?path=…` → guarded delete (owner removes a wrong note), 204; refuses directories.
- Lock-vs-plugin note (docstring): the container's wiki_apply does NOT take our sidecar — a same-second collision is last-writer-wins on inode swap; acceptable for v1 and stated.
