## Part 2 — Findings

### Blockers (D does not work as designed until these are fixed)

**F1. The session-key change gives no conversation continuity.**
- §3's core promise, "every summon of Forge in this Live session continues the same Hermes conversation", is false on our bridge. `_run_call` sends only `user_message` and `system_message`. `AIAgent` gets no `session_db`. Hermes's own reload (`turn_facade_lease.admit_durable_turn_lease`) runs only with a session DB and only after a lease wait. Room turns get continuity because the bridge passes room messages as `conversation_history` (turn:2459), not because of the key.
- Hermes desktop's "same chat session" works because its gateway keeps state.db history. That is the piece we do not have.
- **Fix:** the bridge keeps a per-session-key message list (in memory for the microVM, or saved under the profile) and passes it as `conversation_history` on each call turn, as room turns already do with `result["messages"]` (turn:2468). Otherwise, state honestly that continuity comes only from the transcript delta plus AgentCore memory.

**F2. Ending an exchange kills the agent's background work.**
- §Experience says "work runs in parallel in the background regardless of who holds the floor" and announces results later. Today `close_call` fires `_stop_all_turns(call)` (vc `close_call`), so closing Forge's exchange when Gauge takes the floor stops Forge's run.
- Even if the run survived, its frames are keyed by the closed `callId` and the worker drops them (wh `on_data` filters `payload.callId == x.call_id`).
- **Fix:** decouple run lifetime from the billing row:
  - a Live-session-scoped "voice session" row owns the runs and the frame relay;
  - per-exchange call rows only meter GPT-Live seconds and are closed without `_stop_all_turns`;
  - an explicit Stop (or the room emptying) is the only thing that stops runs.

**F3. A concurrent switch cannot start on the free tier, and doubles holds on credits.**
- §7's "start the new session concurrently with closing the old" needs a second open call row while the first is closing.
- On free mode, `_claim_free` permits exactly one open call per workspace and returns 409 `voice_busy` (vc `_claim_free`).
- On credits, each row takes a full-budget hold, up to `MAX_CALL_SECONDS` = 1800 s (voice_billing.py:21). Two holds during the overlap can return `credits_low` for a workspace that could afford one.
- **Fix:** one billing row per Live session (or per floor-holder change, with the claim *transferred*, not re-claimed). Meter per GPT-Live session through `usage_seconds`, which already exists. Do not mint a new gated call row per switch.

**F4. In-flight frames would be spoken by the wrong agent.**
- `Huddle.thinking` and `Huddle.commentary` always write to the *current* exchange (`self._x`, wh:149-155).
- After a switch, Forge's later frames would go into Gauge's session, in Gauge's voice, carrying Forge's `delegation_id`. That id is unknown to Gauge's session, and OpenAI rejects it: "A non-null ID must identify a known client delegation" (LD:316). This recreates exactly the identity bleed D exists to remove.
- **Fix:**
  - route frames by the run's `agentId`, not by the current exchange;
  - a run whose agent does not hold the floor is buffered and announced later by that agent (F9);
  - never forward an old session's `delegation_id` to a new session; use `null` with the agent named.

### Important

**F5. The concurrent-open code path unpublishes the new voice.** `_Live.aclose` removes every local track named `roomio_audio` (wa:73-79). With two overlapping sessions, closing the old one silences the new one. RoomIO's `lk.agent.state` writes also race. **Fix:** give each session its own track name (`RoomOptions(audio_track_name=f"agent-{agentId}")`, RIO types.py:285) and unpublish only that session's track. Clients key off our own `lightbulb.*` attributes, never `lk.agent.state`.

**F6. Routing before open puts Jev on the critical path.**
- Today Jev runs inside the turn POST while GPT-Live is already open and can say "on it" (vc `_dispatch_turn`, `_ROUTING_TIMEOUT_S` = 3 s).
- In D, the person hears nothing for the sum of:
  - STT final;
  - a worker → backend route call with Jev (up to 3 s);
  - WebSocket connect plus `session.start` (unknown; the third-party report says 2–3 s to first speech);
  - first audio.
- **Fix:**
  - name-match locally in the worker (wt already ports the regex);
  - call Jev only when no name is said;
  - show "joining…" immediately;
  - start the Hermes turn in parallel with the session open (which the design already does).
- Measure the full chain, not only session startup.

**F7. The driven first turn can double-dispatch.**
- If the summoning line is in the seeded history as the newest `user` message, or is passed through `reply_to`, GPT-Live may create its own delegation for it as well. The worker would then POST a second turn.
- With the Live-session key, that second turn queues on the same turn lock (turn:2234-2265). It then supersedes the first through `_claim_turn`, whose stop logic (vc `_dispatch_turn`, "STOP PREVIOUS") kills the first run.
- **Fix:**
  - seed history *up to but excluding* the summoning line;
  - put the line in a `developer` message: "{speaker} asked: … — already handed to your backend self; do not delegate it again";
  - de-duplicate any delegation created in the first N seconds against the driven turn.

**F8. Supersession conflicts with "work runs in the background".** `_dispatch_turn` stops the same agent's previous run in the same call when a new turn arrives. Under D, a quick follow-up to Forge ("and also check X") kills Forge's longer background task. The per-(agent, session) turn lock (turn:2234) also makes a spoken follow-up wait behind Forge's own background work. **Fix:** decide this explicitly. Either steer the running run (the room path already has `steer_run`), or give spoken follow-ups their own run with no supersession, so background work and voice do not share one lock.

**F9. A proactive announcement with per-agent sessions is undesigned.**
- To speak a finished result in Forge's voice, the worker must open Forge's session (startup latency, a billing row, the `MIN_CALL_SECONDS` = 60 budget gate in voice_billing.py:22), with no pinned speaker, and possibly while Gauge holds the floor.
- #3559 is not merged, and its rules assume one always-available voice.
- **Fix:**
  - announcements wait for floor-free silence;
  - open the owning agent's session with a `developer` seed "You finished X: <result>" and an `instructions.append` to say it now. LKD says `generate_reply` "may refuse" after 10 s, so use `instructions.append` (LC:246-256).
  - If the room has moved on (someone else is talking), post nothing and drop to a tile badge.

**F10. Barge-in from a different person is not heard by the open session.**
- Each session is pinned to one participant (wa:89, `participant_identity=speaker`). The model hears no one else, and LKD says "You can't stop the model, but you can stop playing its audio".
- "Gauge, what do you think?" said by someone else while Forge talks is detected only by our STT *final*, after they finish speaking. Forge talks over them until then.
- This depends on #3543, which is unmerged.
- **Fix:** run VAD on every unmuted human. On speech onset from a non-speaker, call `session.interrupt()` / mute output on the floor-holder (playback stop, per LKD), then decide on the STT final.

**F11. Agent names as wake words will false-fire.**
- The regex accepts a name at sentence start, after hey/ok/so, or after ask/tell/get/have (vr:9-18).
- With default names this triggers on ordinary speech: "So growth is up", "Finance said…", "Engineering, can you…", "CEO wants…". Each false fire costs a session open, a billing row and an interruption.
- **Fix:**
  - names count as wake words only when they are *not* default role names, or only as "Hey {name}" / "{name}," with a following pause;
  - "Lightbulb" stays the only always-on wake;
  - log the false-fire rate before enabling.

**F12. Persistent prompt injection through voice notes and rename.**
- Seeded `user` lines carry other people's words into every agent session. That matches OpenAI's own trust split (LC:65, :97: trusted instructions belong in `instructions` or `developer`; user content is untrusted).
- Persistence makes it worse. Anyone in the room, including a vendor shared-channel guest from another org, can say "Forge, call yourself X / always say Y". §6 writes that into Paperclip, into SOUL.md and into every future system prompt. A spoofed "Gauge (agent): …" line spoken by a human looks identical to a real agent line once transcribed. STT mis-hearings also become persisted behaviour.
- **Fix:**
  - only workspace members with owner/admin role can rename;
  - voice-notes writes require the room's owner side, never a guest;
  - echo the change and confirm it ("I'll go by Nova from now on, right?");
  - voice notes are stored as data, framed as "preferences stated by {person}", and length-capped;
  - mark other agents' lines with a source tag we inject (a `developer` header listing which seeded lines came from agents) rather than a name prefix anyone can speak.

**F13. Voice notes cannot ride SOUL.md.** See claim #34. Owner-edited SOUL.md files are never regenerated. **Fix:** a separate backend-owned file (for example `VOICE_NOTES.md`):
- add it to `BACKEND_OWNED_FILES` in both `sync.py` and `hp`;
- append it in the bridge's system-prompt seam (`with_profile_agents_md`) for room, call and Paperclip turns;
- put it in the voice persona.

**F14. Cost and rate limits under frequent switching.**
- Each switch adds the new session's startup seconds plus up to 5 s of overlapped close drain, which [V] assumes is billed. The concurrent slot is held for those seconds. In money that is under 1¢ per switch; the real costs are latency and holds (F3).
- OpenAI concurrency is **per org tier: 25/50/200/300/500 sessions** (MODEL:74-88). It is shared with the backend's WebRTC `/calls` path and doubles briefly during each switch. The design never mentions it.
- **Fix:** check our tier now, and add a metric for concurrent GPT-Live sessions with an alarm at 70% of the tier.

### Minor

**F15. Portuguese voices.** `bossa` and `tempo` are Brazilian Portuguese (LC:41-42). Exclude them from the hash for English agents, and test the nine older realtime voices on gpt-live-1, since OpenAI showcases only the 12 new ones plus marin.

**F16. A rejected voice has no fallback in the worker** (claim #12). Add one: retry `start_live` with `marin` once on a voice-rejection error.

**F17. "Forge and Gauge, …" is not routable today.** `named_agent` returns one id (vr:13-19) and Jev picks one. A multi-agent request needs new routing and an ordering rule.

**F18. Tap-to-talk.**
- Web has no Talk (#3553 title: "no Talk on web").
- iPhone's `talk_start` RPC carries an empty payload (mobile live.tsx:118).
- A tile tap needs `{agentId}` in the payload, validated against the room roster. The caller identity is already server-set (wa:212-216).
- "Lightbulb" with no voice of its own is fine: it only routes. But "Lightbulb, who's here?" now opens the CEO's session to answer.

**F19. A reconnect could exceed the history token cap.** On reconnect, the plugin reseeds from its whole `_history` with no token count (GL:510-568, :455-492). A long exchange that drops could send more than 8,192 tokens and fail `session.start`. Set `max_session_duration` or trim before the start event.

**F20. Default-name invite wording is not guaranteed.** "GPT-Live can't speak a script word for word" (LKD), and `commentary` may paraphrase (LC:260). Use `instructions.append` (LC:258-270) and accept paraphrase. Persist an "asked" flag per agent so the invite happens once.

**F21. Usage attribution.** The new 6-part session key `agent:…:lightbulb:live:<room>:<id>` passes through `report_usage` (turn `run_call_turn`). Confirm the backend usage route does not drop keys it cannot parse (`session_keys.parse_session_key` knows the channel/dm/group shapes).

**F22. Undecided scope.** The backend WebRTC `/calls` path (Voice v2 orb, `packages/shared/src/voice/session.ts:76`) still uses the "Lightbulb" room persona. State whether D replaces it or leaves it alone.

**F23. "Live session" lifetime.** The worker leaves after 15 minutes of room silence (`ROOM_IDLE_SECONDS`, wh:31). A new job is a new `liveSessionId`, so continuity resets then, not only when the room empties. Say so.

## Part 3 — Concrete edits to the design

1. **§3 Continuity.** Replace "every summon … continues the same Hermes conversation" with: "the bridge keeps the Live-session key's message list and passes it as `conversation_history` on each call turn (bounded, as room turns are). A key change alone gives no history (Hermes reloads only with a session DB after a lease wait)." Add the bridge change to the code map.
2. **§3 Billing.**
   - Replace "a call row per exchange" with: "one voice-session row per Live session owns runs and frames; per-floor-holder metering rows record GPT-Live seconds".
   - "Closing a metering row never stops runs (no `_stop_all_turns`)."
   - "The free claim and credit hold are taken once per Live session and extended, not re-taken per switch."
3. **§5 Routing.**
   - "Name-match runs in the worker. Jev is called only when no name is said, and in parallel with showing 'joining…'."

## Overall verdict

D is **possible**: the OpenAI and LiveKit primitives it needs exist and are documented. These hold up:
- 22 voices;
- per-session voice;
- `Agent(chat_ctx)` seeding within 128 messages / 8k tokens;
- null-id appends for work we start;
- concurrent AgentSessions;
- per-second billing.

It is **not buildable as designed**. Four blockers sit in our own code:
- the session key does not carry history (F1);
- closing an exchange kills background runs (F2);
- per-exchange billing rows block a concurrent switch (F3);
- frames go to whichever session is current (F4).

All four are fixable with the edits above. The largest unmeasured risk is the latency of routing plus session open on every switch.
