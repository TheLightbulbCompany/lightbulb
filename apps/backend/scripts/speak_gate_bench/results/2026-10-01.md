## Reading and verdict (hand-written, 2026-10-01; regenerating this file drops this section)

A second run used the `news` prompt (`results/2026-10-01-news.md`, golden set only, $0.009). It changes only the §2.5 news clause, from "news the room is waiting for" to "any pending result, asked for or not". The results:

| golden, threshold 0.85 | §2.5 prompt | `news` prompt | ship bar |
|---|---|---|---|
| SPEAK precision | 1.00 | 1.00 | ≥ 0.95 |
| I2a follow-ups recall | 1.00 | 1.00 | ≥ 0.6 |
| N1 news recall | **0.27** | **0.87** (0.80 at 0.9, 0.90 at 0.8) | ≥ 0.8 |
| I2b open-question recall | 0.00 | 0.00 (0.32 at 0.5) | no bar |
| S2 mentions / S4 addressed / S5 backchannel silent | 1.00 / 1.00 / 1.00 | 1.00 / 1.00 / 1.00 | ≥ 0.98 |
| S1 bystander / S3 mid-thought silent | 1.00 / 1.00 | 1.00 / 1.00 | — |

- **Silence is solved zero-shot.** Across both prompts no SILENT golden row reaches P(speak) 0.7; the highest is 0.65, on an unfinished follow-up, "Nice, and of those how many". That includes the seven rows where news is pending but the line is mid-thought or addressed to a person. Fine-tuning (report option c) buys silence, and we do not need it for silence.
- **The §2.5 prompt fails only on N1.** Jev read "news the room is waiting for" literally: it scores ≥ 0.9 on the 8 rows where someone asks or wonders about the result, and below 0.6 on 18 of the other 22 rows, which are unsolicited results at a break. Widening that one clause fixes N1 without costing any silence.
- **I2b (open questions to the room) does not work.** P(speak) clusters around 0.2–0.5 even though the diagnostic `kind` labels 21 of 25 rows I2b correctly. Jev recognises the situation but still defers to "when in doubt, stay silent". That is acceptable for now, because the report ships I2b last. Raise-hand at P ≥ 0.5 would catch about a third of them.
- **AMI (§2.5 prompt): SILENT 99%, SPEAK recall 8%, BalAcc 0.53**, against the paper's zero-shot range of 0.43–0.61. Jev is heavily silence-biased on "who spoke next" labels, as the prompt intends. AMI I1 here is the corpus's addressee annotation, not "Lightbulb, …" by name, so its 14% says little about our deterministic wake-word I1. As the report argues, AMI is context, not the ship metric.
- **Cost and latency.** All 1,820 calls cost $0.08. The cost was **$0.000046 per call** at ~1.1k input tokens, including the diagnostic `kind` question; the gate alone would be smaller. Latency was p50 562 ms and p90 889 ms at concurrency 8 (news run: 445 / 577 ms). These match prod Jev (417 / 822 ms).

**Verdict: Jev is good enough. Do not train our own model yet.** Use the `news` prompt at threshold **0.85**. The golden set gives precision 1.00, I2a 1.00, N1 0.87 and 100% silence there. Proceed to the report's Step 2 (shadow mode) with N1 first, then I2a. Revisit option (c) only if shadow-mode `cut_in` or `missed` rates miss their targets, or when I2b is wanted.

Caveats:

- The golden set and the prompt fix were written by the same author, and the fix was made after seeing N1's misses on this same set (one iteration). Before relying on that threshold, confirm it on held-out rows, such as dogfood re-enactments.
- There is no candidate filter, so every golden row was judged. The pause length is a constant 900 ms.
