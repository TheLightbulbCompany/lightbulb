### What the failures were

Five tasks failed all three runs on the same journey each time. The harness recorded only pass/fail per journey, so each journey record now keeps its first error message, and the five were re-run once with that in place (13:19–13:5xZ):

- **b02-slotline** and **c06-relaycrm** passed the re-run (0.97, 0.99). Their three failures were builder variance (b02: the clinic-timezone header text and the cancel flow; c06: the kanban column totals), not a task problem. They stay counted against the builder.
- **b05-ledgerly** failed again, identically: the test's `accounts-empty`-or-`accounts-list` locator hit both elements (the app renders an empty note inside the list; Playwright strict mode), and the test required `data-entry-date` on entry rows while the prompt only implied it. Both fixed in the task (locator `.first()`, prompt states the attribute).
- **b09-content** failed again, identically, for three reasons: the journey wrote its second post before the first landed (the same write race the other tasks' helpers already guard), the injection probe signed up as a plain reader, whom the spec forbids from `/admin/posts/new`, so "no payload reached the target form" could never pass, and the journey counted every row of the blog-wide admin list while other journeys' posts were on it. Fixed: the helper waits for the write, the probe signs up as `editor+probe` (new optional `as` field on `sql-injection` probes), the count filters by the journey's own tag.
- **b10-digest** failed again, identically: the journey added two items without waiting for the first add to land. Fixed like the first journey in the same file.

After the fixes, one confirmation run each: b05 0.99 pass, b10 0.98 pass, b09 0.78 (probe fixed; the admin-list count was the remaining defect, fixed after). A clean ×3 of the three fixed tasks is running; its result goes below.
