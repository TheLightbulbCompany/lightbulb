## 0. How connecting works (applies to every row)

- Screen: Connections panel at `thelightbulb.company/chat?panel=connections` (also reached from `/settings/connections`, which only redirects). The same rows show in the Control Panel Integrations tab. Source: `app/settings/connections/page.tsx`.
- Who clicks: an organisation admin only. Every connect, disconnect and BYO-app route calls `require_org_admin` (`routers/connections.py` lines 523, 583, 657, 828, 956, 982, 1023). Non-admins see disabled buttons (`ConnectionsList.tsx`).
- The agent cannot connect anything. It can only print a sign-in link on request (`lightbulb-connect.sh link <provider>`) and send the owner to Connections (`references/integrations.md`).
- Phone: the iPhone app lists MCP servers read-only and links out to the web panel (`mobile/.../control/integrations.tsx`, `MANAGE_INTEGRATIONS_URL`). Connecting needs a browser.
- Scope of a connection: one per workspace (owner), not per agent. CLI credentials are copied identically into every agent profile in S3 (`hermes_cli.py`, "Per-agent, like mcp-tokens"). Google is the only exception: several accounts per workspace, and an agent can be assigned one (`google_identity.py`, `GOG_ACCOUNT`).
- Three delivery rails (`references/integrations.md`):
  - `mcp`: tools appear in the agent's toolset.
  - `cli`: a binary in the microVM shell (`gog`, `gh`, `aws`, `xurl`).
  - `skill`: a bundled skill reads the credential.
- Brokered refresh: for MCP providers with `brokered_environments: [dev, prod]` the backend keeps the refresh token in Secrets Manager and hands the agent a short-lived access token each turn via `POST /credentials/u/{owner}` (`routers/runtime_rpc.py`, `access_token.py`). Microsoft 365 and Sentry use the same path (`refresh_owner: backend`). If refresh fails the row flips to `reconnect_required` and the agent loses the tool (`access_token.py::_mark_reconnect`).
- Environment gates (`registry.py` lines 477-510, 580-615): `environments` hides a provider outside the listed envs. `owner_allowlist` lets named owners in. A hidden provider is not listed and cannot be connected. `offer_request_access` is not set on any provider, so gated ones are fully hidden.
- Catalog check: `GET /api/v1/platform-info` lists only providers visible in the env and supported by the Hermes runtime (`platform_info.py`, `apply_connection.runtime_supported`). `attio_api` and `apollo_api` are `backend_only`: they feed the owner's Leads tab and give the agent nothing.
- Standing person steps (not repeated below): sign in to any third-party site in the shared browser, type every code and CAPTCHA there, any payment, approval of outbound words (`boundaries.md`, `surfaces.md`).

## 3. Findings that change the plan

1. Every connected service is per workspace and every connect is an admin click or paste. There is no way for an agent to start a BYO or paste connection (`references/integrations.md`).
2. Two connectors need the owner's own developer app: Google (Cloud project) and X (developer app). Google is the heaviest first step, and an External app in Testing loses access every 7 days.
3. Writes are limited by the grant, not the tool:
   - Microsoft 365, Linear, Sentry, Apollo: read-only scopes.
   - Shopify: the skill forbids mutations without per-conversation confirm, and scopes depend on the owner's app.
   - Cloudflare, Stripe, Attio, Intercom: the write set is set by the vendor consent screen; tool lists are not in the repo.
4. Two connectors are hidden in prod: Meta Ads and Instagram (two allowlisted owner ids only).
5. Three connectors hold a single-writer rotating token and cannot be restored from the backend after a wipe: Google (gog keyring), QuickBooks (100-day rolling), X (single-use refresh). Instagram needs use at least every 60 days.
6. Stripe Projects (account creation on the company's Stripe identity) is off unless `STRIPE_PROVISIONING_ENABLED` is set; the prod value is not in the repo.
7. Docs mismatch: `references/integrations.md` and the capability docs still refer to `~/.openclaw/lightbulb-facts.json` and to Parallel as an MCP; the registry shows `PARALLEL_API_KEY` as a profile env key.
