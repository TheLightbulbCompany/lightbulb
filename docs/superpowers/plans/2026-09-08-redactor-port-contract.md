## Recommendation

Carry the gateway chunk-boundary fix directly. Replace the globally permissive shell-header heuristic with an input-context exception for demonstrably executable environment references. The production requirement is preservation of agent-generated executable curl references through persistence and replay, including `$OPENCLAW_HOOK_TOKEN` and `$PAPERCLIP_API_KEY`. A plain logged header containing `$abc` is not evidence of a shell expansion.

The security contract below is concrete; the shell-input adapter is not yet an implementation-ready three-file port. Native source provenance and a bounded Bash parser exist, but they are not currently connected for shell source. That integration needs a focused runtime proof after the package-manager gate. Do not report both carried fixes implemented merely by adding a pattern set and prefix check.

## Proposed narrow behavior

The exception belongs to native input-source policy. Generic logs, user messages, diagnostic payloads, output text, HTTP/JSON header values, and unowned source-looking strings keep existing credential masking.

| Input in a verified shell command/header argument | Required behavior |
| --- | --- |
| `curl -H "Authorization: Bearer $OPENCLAW_HOOK_TOKEN" ...` | Preserve the complete executable reference. |
| Same with `$PAPERCLIP_API_KEY`, `${NAME}`, `${NAME:-}` | Preserve when the entire credential is the validated reference, with no literal fallback or concatenated credential suffix. |
| Corresponding Basic/Bot/proxy-auth, other existing authorization schemes, credential-style and gateway header patterns | Apply the same context and complete-value rule; no header-family-specific weaker exemption. |
| The historical `$(printenv OPENCLAW_HOOK_TOKEN)` fixture | Can be preserved as the exact parser-proven single `printenv` call with one identifier argument and no other syntax. This is an explicitly bounded environment accessor, not permission for arbitrary command substitution. |
| `${TOKEN:-literal-credential}` or `$(printf literal-credential)` | Mask the complete credential expression, including the embedded literal. Do not merely mask the regex's truncated `$(printf` capture and leave the argument visible. |
| `${TOKEN:-literal with spaces}`, nested substitutions, `$TOKEN-literal-credential`, `${TOKEN}literal-credential` | No whole-value exemption. Mask the complete unsafe credential value. |
| Single-quoted header containing `$abc`, escaped `\$TOKEN`, raw literal `$abc`, `$`, `$$`, `$1`, `$2b$12$...` | Mask the literal; do not infer execution from a dollar prefix. A syntactically real `$abc` expansion in a verified expanding argument is a reference and may survive. |
| `$`-prefixed registered secret, including one that happens to spell a valid variable reference | Registered value redaction wins. Never restore the original bytes afterward. |
| Configured pattern matching the reference, including an exact built-in pattern source configured explicitly | Custom pattern wins; no preservation callback on that pass. |
| Parse failure, work-limit exhaustion, unsupported language, ambiguous ownership or offset mapping | No syntax exemption; use existing diagnostic masking. For a successfully identified unsafe header argument, mask its whole credential span rather than a truncated capture. |

The variable grammar should be a complete POSIX name (`[A-Za-z_][A-Za-z0-9_]*`), not a prefix test or secret-name allowlist. Permit only the complete simple forms needed above initially. No evaluation, `printenv` execution, fetching credentials, or validation against actual environment values is involved.

For source header credentials that need masking, use a full `***` credential placeholder while retaining necessary source quote delimiters. Native diagnostic hints can shrink on the second header pass; full source masking provides the existing source policy's repeat-redaction stability. Require the preserved reference and masked literal outcomes to be identical after guard redaction, storage redaction, SQLite close/reopen, and the next provider request.

Do not implement token shielding by placeholder-and-restore around the entire redactor. That can defeat registered-secret/custom-pattern authority. Nor should source spans authorize bypassing all patterns: only the specific built-in header match may be exempt, while vendor-secret, structured-auth, form, exact-value and custom redaction remain active.

## Smallest implementation surface to investigate

The gateway patch is two additions to `src/logging/redact-patterns.ts:CHUNK_UNSAFE_PATTERN_SOURCES` and a table-driven regression in `src/logging/redact.test.ts` covering both colon and equals gateway forms. Keep the existing full-string route in `redactText`; no chunker redesign.

For header preservation, use these existing seams rather than a new parser framework:

- `src/logging/redact.ts:redactInputTextWithSourcePolicy`, `redactText`, `redactMatch`: add a source-only complete-header-value decision alongside the existing assignment callback. Keep the callback out of the custom-pattern pass and every generic/output API. Define full-span masking for unsafe source credential expressions. `redact-patterns.ts` may identify the built-in header family, but membership alone must confer no exemption.
- `src/logging/redact-source.ts`: keep Acorn assignment behavior intact. Add or call shell-specific treatment only when trusted input provenance identifies shell language; do not try to parse all JavaScript strings as Bash. A small sibling shell-source helper is preferable if mixing the languages makes this file larger or obscures the existing policy.
- `src/infra/command-explainer/tree-sitter-runtime.ts` and, only if needed, `extract.ts`: reuse bounded native parsing and exact source offsets. Add only the minimum parser-owned header/expansion inspection required; do not import the lossy display tokenizer, add a dependency, or fork a Bash grammar.
- `src/agents/transcript-code-mode-source.ts` source-slot capture/read/copy functions and `embedded-agent-runner/run/attempt-client-tools.ts` / `attempt-stream.ts`: use the existing private ownership route for prepared native shell-tool input and preserve it through both append passes. A public boolean, tool-name-only test, or a model/plugin-supplied `language: "shell"` is insufficient. Determine the shell owner from prepared native tools, analogously to the current Code Mode owner.
- `src/agents/transcript-redact.ts`: select the correct source treatment from that private language/provenance fact; preserve ordinary output and diagnostic dispatch.

This names candidate change seams, not a commitment to edit all files. Source inspection found no ready synchronous, privately owned shell-span API. The parser initializes asynchronously, while `redactTranscriptMessage`, `redactInputTextWithSourcePolicy`, and the SQLite write contract are synchronous. A practical adapter must prepare native parser state/facts at an existing asynchronous owner boundary and preserve/revalidate them across redaction-induced text changes. Reusing stale offsets after exact/custom or earlier built-in replacements is unsafe. Do not convert the synchronous transcript stack to async, add broad source serialization metadata, or create a generic span-rewriting framework for this fix. Resolve the smallest viable adapter with a focused prototype after the approved runtime is available; failure to do so is a real integration blocker, not permission to restore the global heuristic.

Code Mode is a separate proof case: a JS/TS `command` field is source code, not shell language. A string containing curl inside Code Mode must be linked to a real nested shell-tool input before shell exceptions apply; merely being an Acorn string literal or containing `curl` is insufficient. The current private carrier does not provide that nested relationship. Verify the actual founder call surface before claiming this path covered. The bounded review did not establish a native nested-shell-to-outer-source mapping.

## Decisions and evidence limits

No human choice is needed to reject the global `$` heuristic, retain custom/registered-secret precedence, or mask literal fallback/substitution credentials under the current safety requirements.

There is one potential product-scope decision: the shipped test treated arbitrary shell-expansion prefixes and plain text headers as preservable. This proposal preserves executable input references and the concrete simple `printenv NAME` case, while generic diagnostic/output `$abc` and arbitrary substitution bodies lose that permissive behavior. If “preserve shipped behavior” requires arbitrary `$(...)` source expressions or code examples returned by tools to remain verbatim, that broader requirement needs explicit clarification and additional native source/literal analysis; it cannot safely be satisfied by the old heuristic. Keep the stricter contract as the default. This is a semantic boundary, not a request to weaken security.

Pinned package metadata requires `pnpm@12.3.4` with the checked-in integrity. `pnpm-workspace.yaml` has `minimumReleaseAge: 10080` and `minimumReleaseAgeStrict: true`. The parent reports the exact pinned-pnpm age exception is pending; this review neither retried the install nor independently adjudicated that approval. No alternate pnpm, package-manager guard change, alternate dependency tree, manually transpiled test subset, or replacement test runner was used.

Until that gate and the normal pinned install are available, all proposed behavioral assertions above remain unexecuted. Source evidence cannot prove installed parser node shapes/offset semantics, callback/custom precedence after implementation, double-write idempotence, SQLite replay, actual model tool ownership, Code Mode nested-shell mapping, or founder curl execution.
