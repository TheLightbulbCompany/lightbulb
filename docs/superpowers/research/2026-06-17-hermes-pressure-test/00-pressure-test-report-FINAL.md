## 3. The multi-agent finding (headline) — CONFIRMED HARDER

**Hermes has no first-class multi-agent model. One daemon = one persona, one SOUL, one session namespace literally hardcoded as `agent:main`.** Re-verified this pass: `gateway/run.py:1031` matches only `parts[0]=="agent" and parts[1]=="main"`; `_create_agent` (`api_server.py:851-912`) takes `ephemeral_system_prompt`/`session_id` but **no `agent_id`**; `/v1/models` returns exactly one model (`:943-962`); the developers' own `gateway/status.py:9-11` calls "multiple agents running concurrently" a *future* feature. The only "two at once" mechanism is `delegate_task` — ephemeral, non-addressable child workers (`delegate_tool.py:133` `MAX_DEPTH=1`, `:153` in-memory map), the opposite of two persistent peers an orchestrator routes by name. **attack01 is the independent confirmation and it confirms harder than the interim:** the §4 port methods `list_agents`/`create_agent`/`list_sessions(agent_id)`/`export_agent` have **no Hermes-side key to resolve** — they degrade to "which persona string + which session prefix the backend invents." Agent identity MUST become a backend-held registry, re-sent on **every** `/v1/runs` (the daemon persists no notion of "who Friday is").

**New nuance attack01 added that the interim got wrong:** the interim called the concurrency "explicitly designed, clean." It is not fully clean. `init_agent` writes **`os.environ["HERMES_SESSION_ID"] = agent.session_id` unconditionally on every agent build** (`agent/agent_init.py:867`, verified this pass), with the concurrency-safe ContextVar set *after* (`:870`). The code's own comment (`:861-866`) admits the env write is a CLI-mode fallback. Under two simultaneous Friday+Atlas runs this is **last-writer-wins process-global state**; any tool that reads the env fallback instead of the ContextVar mis-attributes the session. Concurrency at the run-dispatch level is real (`asyncio.create_task` + `run_in_executor`, no global lock, cap 10), but the session-id env leak is a genuine cross-run hazard the spec and interim both missed.

**Design consequence (unchanged, now independently endorsed):** "two interchangeable adapters behind one port" holds for the **Transport** facet but **breaks for the agent-model facets**. Net-new backend work the spec doesn't budget: a per-owner agent registry (persona text, per-agent skills/MCP/cron mapping, session-prefix convention, marketplace-agent identity) in Isol8's own store. This is "build a thin agent-orchestration layer in the backend," not "render a profile into a file." `seed_owner_agents` on Hermes is a no-op; marketplace deploy creates no Hermes agent. **This remains the single finding most likely to move the estimate and re-shape the architecture diagram.**

## 4. Newly-confirmed / newly-surfaced risks (independently verified)

1. **A15 ⊗ A8 are mutually antagonistic (attack02 + attack07 escalation).** Single-writer `maxPercent=100` (needed for SQLite, A8) means every deploy is a hard task replacement; `/v1/runs` state is fully volatile (A15) and `disconnect()` does not drain runs — so **every redeploy guarantees orphaned in-flight runs with no terminal frame**, including a *graceful* SIGTERM rollout. The two load-bearing mitigations fight each other. Backend must drain runs before any deploy; client watchdog must treat "no terminal ever + GET 404" as a first-class state.
2. **`os.environ["HERMES_SESSION_ID"]` last-writer-wins (attack01, verified).** Process-global session-id write on every agent build (`agent_init.py:867`) — a cross-run mis-attribution hazard under concurrent Friday/Atlas runs. NEW; not in the interim.
3. **Credential write-back, not just read (attack03 + attack07).** The pool writes rotated anthropic tokens back to `~/.claude/.credentials.json` (`credential_pool.py:767-779,872-880`). This turns "don't use it" into "must actively strip it from the image" — a security-review finding. The interim captured the read side; the write-back is the sharper half.
4. **Empty `API_SERVER_KEY` = open container (attack03, verified posture).** `_check_auth` allow-all when key falsy (`api_server.py:750-751`); the bind guard only protects non-loopback binds. A misconfigured/empty key on the task def is a real open-container footgun for the port.
5. **`/api/jobs*` cron CRUD under the same single bearer (attack07).** A leaked key is not "read one chat," it's "schedule persistent arbitrary code execution" (`api_server.py:3410-3417`). Belongs in the threat model.
6. **Abort is advisory (attack02).** `/stop` relies on `agent.interrupt()`; `task.cancel()` cannot preempt the executor thread (`:3334-3337`). A run stuck in a tool/LLM call keeps burning tokens after `/stop` returns `stopping` — metering must not assume tokens halt at `/stop`.
7. **Subagent progress invisible on the wire (attack02).** `_thinking` and `subagent_progress` are deliberately not forwarded (`api_server.py:2858`) — a real multi-step/delegated UX gap.
