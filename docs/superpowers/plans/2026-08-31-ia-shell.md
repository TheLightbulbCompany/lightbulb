# IA Shell — the business-noun left nav Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** The workspace sidebar speaks the spec §5.1 IA — business-outcome groups (Work, Money, Growth, Operations, Knowledge, Company) — with every visible item routing to a live panel, no dead ends, ⌘K covering the same set, and the retired control-sidebar dead code deleted.

**Architecture:** Evolve, don't rebuild: `CompanyNav.tsx` already renders grouped panel items in the sidebar; this plan regroups it to the target IA and makes the group list the single declaration new tabs append to. Panel identity stays in `panelRegistry.ts` (the sole authority). Items whose tab doesn't exist yet DO NOT RENDER — groups grow as tabs land ("new tabs arrive with the data that fills them"); a group with zero live items doesn't render either. Mobile is untouched: the `?panel=` grammar (`teams-*` keys) must not change — regrouping is presentation only.

**Tech Stack:** Next.js 16 / React 19, Tailwind v4 arbitrary-value classes over brand tokens, lucide-react, existing panel plumbing (`openPanel`, `TeamsPanelRouter`).

**Spec:** `docs/superpowers/specs/2026-08-28-owner-data-plane-design.md` §5.1 (target IA), §5.2 (mechanics + design language). UX preamble: the controller's tab-UX notes — the sidebar's nouns are business outcomes; chat is where the owner says what they want, tabs are where they see state and approve.

## Global Constraints

- `panelRegistry.ts` stays the sole source of panel identity; renames go through `RETIRED_PANEL_ALIASES`, never deletion — `layoutStorage` and mobile's `webLinks.ts` depend on the grammar. **No `teams-*` key may be renamed or removed** (mobile builds those URLs as strings with no compile check).
- Colours/fonts: brand tokens only (`--edge`, `--cream*`, `--midnight*`; `src/__tests__/brandTokens.test.ts` must pass). Row idiom: keep `CompanyNav`'s existing Tailwind row classes verbatim; group labels keep `.agent-section-label`.
- No dead ends: an item renders only if its panel resolves via `describePanel` today. No placeholder/"coming soon" rows in this PR.
- `pnpm exec tsc --noEmit` clean; scoped vitest (`src/components/chat`, `src/components/workspace`, `src/components/teams/command-palette`, `src/__tests__/brandTokens.test.ts`) green; existing `ChatLayout.unifiedSidebar` assertions must keep passing.
- Every task commits separately; run scoped tests per task, full suite rides CI.
