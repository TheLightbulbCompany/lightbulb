# One Lightbulb Slack app — design

**Status:** founder-reviewed 2026-09-04, open items resolved; next step is the
Phase 1 implementation plan. Supersedes the per-owner "create your
own Slack app" wizard as the default Slack path.

**Goal.** A workspace admin finds Lightbulb in the Slack Marketplace, clicks
Add to Slack, and a few minutes later their whole team is talking to Friday in
Slack — with streaming, threads, approval buttons, shortcuts, App Home and Agent
View — having never opened flickmeon.ai. Existing owners get the same button
inside the product.

**Non-goals (v1).** Enterprise Grid org-wide installs; modals; token rotation;
per-agent Slack identities (one scope away — see §9); a warm pool of
pre-provisioned containers; Discord/Teams parity.

---

## 1. Constraints that shaped this (all verified 2026-09-04)

Slack platform:

- **Socket Mode is banned from the Marketplace.** "Apps using Socket Mode are
  not currently allowed in the public Slack Marketplace" / "using HTTP is a
  requirement" (docs.slack.dev, *Using Socket Mode*, *HTTP vs Socket Mode*).
- **Per-workspace WebSockets are impossible regardless.** `apps.connections.open`
  accepts only an app-level `xapp-` token, generated by hand in Basic
  Information — OAuth never mints one. Every install of a distributed app shares
  the same `xapp-`, and Slack caps an app at 10 concurrent sockets and delivers
  any payload to any open socket. This — not container isolation — is why every
  owner builds their own app today.
- **Kill switch:** event subscriptions are disabled only when **>95% of delivery
  attempts fail within 60 minutes** (non-2xx, >3 s, SSL, >2 redirects). Retries:
  immediate, +1 min, +5 min, with `x-slack-retry-num`; `x-slack-no-retry: 1`
  suppresses retry for one event.
- **Eligibility floor:** ≥10 active workspaces and ≥10 weekly active users, held
  throughout review. Review is ≤10 business days preliminary + ≤10 weeks
  functional. Scope minimization is enforced: every scope needs a feature-linked
  justification; `*:history` + AI draws "additional scrutiny"; `admin.*`,
  `search:read`, user-token `*:history` are effectively refused.
- **Unlisted distributed apps** since 2025-05 get `conversations.history` /
  `.replies` throttled to **1 req/min, 15 objects** (listed: Tier 3, 50+/min,
  1000 objects). Listing is worth real money, not just distribution.
- Forbidden: training on Slack data (needs attestation), "AI making
  consequential decisions without human review" (our approvals rail becomes a
  listing requirement), MCP-only apps, posting to #general by default.

OpenClaw `@openclaw/slack` 2026.8.1-beta.3 (fork tag `v2026.8.1-isol8.1`;
byte-identical to upstream — our fork carries no Slack patches):

- Three transports: `socket` (default), `http`, `relay`. **Relay is a stub with no
  Slack ingress**; it admits `type:"message"` only — no `app_mention`, reactions,
  interactivity, slash, App Home, Agent View — and refuses Enterprise Grid. Dead
  for this purpose.
- `mode:"http"` registers `channels.slack.webhookPath` (default `/slack/events`,
  **must be unique per account**) on the container gateway with
  `auth:"plugin"`, which means **no gateway credential at all** — the route
  authenticates itself via Bolt's HMAC on `channels.slack.signingSecret`
  (config-only, no env var). Upstream's own test proves proxied traffic carrying
  `X-Forwarded-For` is still served on plugin routes
  (`src/gateway/server.plugin-http-auth.test.ts:510-591`).
- Multi-agent routing is already solved by top-level `bindings[]`
  (`src/routing/resolve-route.ts:616-829`): peer → team → account → default.
- **No OAuth install flow, no installation store, no `app_uninstalled` /
  `tokens_revoked` handlers, no `views.open` (modals).** Bolt acks first and
  unconditionally; replies go through the Web API (`response_url`,
  `chat.postMessage`), never the HTTP response body — so an async hop costs no
  surface except modals, which we don't raise.
- Native streaming (`chat.startStream/appendStream/stopStream`, task cards) is on
  by default. Per-agent outbound identity (`resolveAgentOutboundIdentity` →
  `username`/`icon_url`) works with `chat:write.customize`, degrading gracefully.
- The generated manifest omits `settings.interactivity` and `features.shortcuts`
  — buttons are dead on arrival unless added. `assistant_view` is gone; the
  plugin targets `agent_view`, and the migration is irreversible per app.

Lightbulb:

- Owner = Clerk `org_id` or `user_id` (`core/auth.py:96-98`); every container,
  billing row and Paperclip company keys on it.
- Free tier is personal-only (`user_provision.py:63-65,84`); orgs are blocked by
  `_team_billing_required_gate` (`provision_gate.py:197`).
- Channels are paid-only via `has_always_on_entitlement` (`provision_gate.py:136`)
  at `routers/config.py:151-157`. Seven other call sites share the predicate
  (hooks, Paperclip triggers, Meta, routines, nightly CEO, org invites, Stripe
  Connect). Inbound agent email is **not** gated — precedent for a free-tier
  inbound surface (`ses_inbound.py:288`).
- **No inbound surface can wake a parked container.** `start_user_service` is
  reachable only from authenticated routes; hooks/SES/Meta/Paperclip use
  `resolve_running_container`, which returns nothing for a stopped box. A trial
  container parks ~3 min after the last browser tab closes
  (`connection_pool.py:48,58,3583`).
- Backend is `desiredCount: 1`, no autoscaling, one uvicorn worker, by design
  (in-process WS pools; `docs/superpowers/specs/2026-05-30-multi-instance-…`).
  API GW prod stage throttle is **200 rps / 500 burst, shared with all REST**
  (`api-stack.ts:97,222-224`).
- Today's Slack path: `BotSetupWizard.tsx` PATCHes `channels.slack.accounts.<agentId>
  = {mode:"socket", appToken, botToken}` in **plaintext on EFS**; account id ==
  agent id; `config_patcher.py:179-214` adds the sibling `route` binding;
  `ecs_manager.py:152-181` + `containers/config.py:2417-2458` carry channel
  accounts across a reprovision (CLAUDE.md's "only MCP + Projects env survive" is
  incomplete). `hook_token` is the existing "secret in task-def env, `${VAR}`
  placeholder in openclaw.json" precedent (`config.py:2133-2142`).
- `routers/meta_webhook.py` is the existing one-app-URL webhook: signature at
  the edge with the platform secret, routed by a payload id, 200 after signature
  regardless of downstream. `routers/hooks_proxy.py` is the existing
  backend→container forward leg (raw body, `discover_ip`, port 18789).
- Prod alerting is dead: both SNS topics were recreated by the rebrand with zero
  subscribers; the warn tier cannot publish at all (EventBridge targets replace
  the TopicPolicy; PR #1947 stale).

## 2. Product decisions (founder, 2026-09-04)

| # | decision | consequence |
|---|---|---|
| 1 | **A Slack workspace is always a Clerk org.** | Team name → company name; org per workspace; a person in two workspaces is two orgs. No personal→org migration exists or is needed — a personal owner who installs gets a *new* org container; their personal one is untouched. |
| 2 | **Slack install is free.** Slack-minted orgs get `trial_local` (same $3/day cap, same 3-day window). | Two gate sites learn to admit a Slack-origin org. The paywall on *autonomy* (routines, webhooks, nightly CEO, heartbeats) does not move: free Slack = reactive chat with Friday, the same thing the free web tier gets. After the window (or the daily cap) Slack gets the same templated "upgrade" reply the web app shows — §3.7. |
| 3 | **A seat is a login.** Slack peers are free and never touch Clerk; web access needs a Clerk invite = a seat. | Prices unchanged. Seat *meaning* changes from "people who use Friday" to "people who log in." Heavy Slack usage is captured by Bedrock credits via Metronome. Per-member usage analytics collapse onto the owner for peers (analytics only; billing unaffected). |
| 4 | **BYO-app path stays, demoted** to "advanced: use your own Slack app." | Mixed socket/http accounts coexist per container; nothing forces a cutover. |
| 5 | **One bot, Friday by default;** per-channel overrides ready; agent faces later. | Account-wide binding → Friday; `peer` bindings ahead of it. `chat:write.customize` when wanted. |
| 6 | **Synchronous proxy in the backend** (ponytail). | See §3; Lambda+SQS is the named upgrade path, not v1. |

Two lines these decisions draw:

- **Peer DM privacy — not P0.** A peer's DMs with Friday become container
  sessions the org admin can browse in the web app (Viktor guarantees the
  opposite). v1: one sentence on the install page + App Home ("your admin can
  see conversations with Friday"). Hiding peer-DM sessions from the admin list
  is a small follow-up, not a launch gate.
- **Approval authority.** `execApprovals.approvers` = the installer's Slack user
  id; web members' linked Slack ids are added when they pair. Peers cannot
  approve by default.

## 3. Architecture

### 3.1 Transport

```
Slack ──HTTPS──► api[-env].flickmeon.ai/api/v1/slack/events   (own route throttle)
                    routers/slack_app.py  (shape: meta_webhook.py)
                    1. url_verification → echo challenge
                    2. verify v0 HMAC with app signing secret; |now-ts| ≤ 300 s
                    3. drop own-bot echoes (event.user == install.bot_user_id, or event.bot_id set)
                    4. install = slack_installs.get(team_id)   miss → 200 + log
                    5. blocked (trial expired/capped) → templated reply, 200 + x-slack-no-retry
                    6. ip = discover_ip(owner)   (NEVER resolve_running_container — its 5 s TCP probe)
                       none & parkable → start_user_service; return 503 ("waking")  → Slack retries at +1 min
                    7. dedup: webhook_dedup.record_event_or_skip("slack:{team}:{event_id}", ttl=1h)
                       — recorded ONLY here, just before the forward: a 503 leaves no row, so Slack's
                       retry (same event_id) is delivered instead of read as a duplicate
                    8. re-sign: X-Slack-Signature = v0=hmac_sha256(hook_token, f"v0:{ts}:{body}")
                    9. POST http://{ip}:18789/slack/events/{team_id}  raw body, X-Slack-Request-Timestamp,
                       Content-Type, httpx timeout 2 s
                   10. relay container's status; on timeout → 200 + metric (per-owner loss, never app-wide 5xx)
Container ──► @openclaw/slack mode:"http", auth:"plugin" — full surface, streams back via Web API
```

Why synchronous (ponytail ladder): the kill switch needs 95 % failure over
60 min — unreachable by any outage we have had; the shared 200 rps throttle is
one CDK property (route-level throttle on this route); a wedged container is a
2 s timeout + 200; cold wakes ride Slack's own +1 min retry; and a sync proxy
parks nothing, so deploys lose nothing. `meta_webhook.py` + `hooks_proxy.py` +
`webhook_dedup` already exist. Warm path ≈ 100–300 ms.

`# ponytail: backend is on the ack path; fine to low-hundreds events/s. Move the
ack to a slack-ingress Lambda + SQS (designed: signature+dedup+SendMessage in
~100 ms; backend becomes a scheduled_worker-style consumer with DelaySeconds for
cold wakes; ~$4/M events) when sustained load passes ~50 events/s or Slack's
failure email arrives.`

Named ceilings: a wake >5 min loses the event (pathological boots only — the
11-agent restore case); an over-cap owner's messages are dropped deliberately
with `x-slack-no-retry`; own-bot echoes are filtered at step 3 so one tenant's
fan-out can't eat the platform's REST budget.

### 3.2 Credentials — nothing plaintext on EFS

| secret | store | reaches the container as |
|---|---|---|
| App `client_id`, `client_secret`, `signing_secret` | `platform_oauth_app_store` name `slack` (widen `_get_sync` to pass `signing_secret`); seeded by `scripts/set_platform_oauth_app.py` | never — backend only |
| Per-workspace `xoxb-` bot token | `integration_secret_store.put(owner, f"slack/{team_id}", {bot_token, bot_user_id})` — owner-prefix wipe for free | ECS task-def `secrets:` entry `SLACK_BOT_TOKEN_{TEAM_ID}` → SecretRef `{source:"env", provider:"default", id:"SLACK_BOT_TOKEN_T…"}` (id regex `^[A-Z][A-Z0-9_]{0,127}$` — team ids pass, agent ids don't) |
| Per-tenant signing secret | **already exists: `hook_token`** on the containers row, already `OPENCLAW_HOOK_TOKEN` in every task-def | SecretRef `{source:"env", provider:"default", id:"OPENCLAW_HOOK_TOKEN"}` |

The app-wide signing secret never leaves the backend. Threat check: an owner with
a shell reads their own `hook_token` and can forge events only for their own
container — already true of `/hooks` today; cross-tenant forgery needs another
owner's `hook_token`, which is nowhere in their container.

**The per-user task's EXECUTION role fetches `secrets:` at task start** — `container-stack.ts`'s `PerUserTaskSecrets` statement must grant `GetSecretValue` on `lightbulb/{env}/integrations/*` (it covered only `user-keys/*`; the backend task role's integrations grant is a different role). Without it the install roll stops the old task and cannot start the new one.

Install ordering (a `${VAR}` that is missing at boot throws
`MissingEnvVarError`): write the task-def with the new secret →
`refresh_task_definition` (existing primitive; add a `secrets=` parameter) →
wait PRIMARY → *then* patch the account block. One roll per install; installs
are rare. Token rotation is skipped: optional for Marketplace and incompatible
with tokens riding the task-def. Uninstall MUST drop the task-def `secrets:` entry (`refresh_task_definition(drop_secrets=[...])`) BEFORE the secret is force-deleted — a dead secret ARN in `secrets:` makes every later relaunch of the owner's task (Spot interruption, OOM, resize) fail. A stale `environment` var would be harmless; a stale `secrets:` entry is not.

### 3.3 Routing table

`isol8-{env}-slack-installs` (`database-stack.ts`, beside `agent-email-addresses`):

```
PK   install_id = team_id ("T…")            # enterprise_id ("E…") reserved for v2
GSI  by-owner   PK owner_id
     owner_id, agent_id (default agent), bot_user_id, app_id, scopes[],
     installer_slack_user_id, installer_member_id (Clerk), installer_email,
     installed_at, status active|revoked,
     token_secret_name, channel_overrides {C…: agent_id}
```

Conditional put: `attribute_not_exists(install_id) OR owner_id = :owner OR #st = :revoked`
— the same owner re-installs in place; a different owner gets 409 unless the
prior install is revoked (no workspace hijack; legitimate hand-over after
uninstall).

Cases: one workspace ↔ one owner (one row); an owner with two workspaces (two
rows, two account blocks, two task-def secrets, two bindings); reinstall (token
overwritten in place); Enterprise Grid (**refused in v1** — `org_deploy_enabled:
false`; the plugin's org-install mode forbids pairing, bindings and allowlists).

### 3.4 Config shape

```json5
"channels": {
  "slack": {
    "enabled": true,
    "streaming": { "mode": "progress" },
    "accounts": {
      "T0123ABC": {                                   // account id = team_id
        "mode": "http",
        "webhookPath": "/slack/events/T0123ABC",      // unique per account
        "botToken":      { "source": "env", "provider": "default", "id": "SLACK_BOT_TOKEN_T0123ABC" },
        "signingSecret": { "source": "env", "provider": "default", "id": "OPENCLAW_HOOK_TOKEN" },
        "dmPolicy": "open", "allowFrom": ["*"],       // peers, not members (decision 3)
        "execApprovals": { "approvers": ["U_INSTALLER"] },
        "slashCommand": { "enabled": true, "name": "lightbulb" }   // default is disabled
      }
    }
  }
},
"bindings": [
  { "type": "route", "agentId": "<atlas>",  "match": { "channel": "slack", "accountId": "T0123ABC", "peer": { "kind": "channel", "id": "C0456" } } },
  { "type": "route", "agentId": "<friday>", "match": { "channel": "slack", "accountId": "T0123ABC" } }
]
```

No `appToken`, no `xapp-`, no app-wide secret on EFS or in a tenant task-def.
The vendored schema gate passes (`channels.<provider>` is `{}`).

Reprovision durability: `_provision_channel_accounts` reads
`slack_installs.list_for_owner` (plus legacy socket accounts from the file for
mixed mode) instead of the old EFS file, so reprovision, roll and image bump
regenerate identical account blocks and bindings from the table + Secrets
Manager. The `is_bedrock_trial` exclusion at `config.py:2429` is *replaced* by
"re-inject when the owner has an active install row" — under decision 2 a trial
owner may legitimately hold one.

### 3.5 Install lifecycle

**Start.** `GET /api/v1/slack/oauth/start` → Slack authorize URL with `state` =
Fernet-signed `{owner_id?, member_id?, nonce, ts}` (`core/encryption.py`, the
ChatGPT-OAuth pattern). Two entry points: our "Add to Slack" tile (signed in,
`owner_id` set) and the Marketplace button (cold, no `owner_id`).

**Callback.** `GET /api/v1/slack/oauth/callback?code&state`:

1. Consume `state`. Exchange `code` via `platform_oauth_app_store.get("slack")`
   → `access_token` (bot), `team.{id,name}`, `authed_user.id`, `bot_user_id`,
   `scope`. Installer email from Sign in with Slack `openid email` (one scope,
   installer only — preferred over `users:read.email` on the whole workspace).
2. Resolve the org (§3.6).
3. `integration_secret_store.put(owner, f"slack/{team_id}", …)`; conditional put on
   `slack-installs`; `integrations_repo.put_status(owner, "slack")` for the
   Connections card.
4. If the org has no container: `billing_repo` trial row (Slack-origin) →
   `ensure_user_ready(synthetic AuthContext(user_id, org_id, org_role="org:admin"))`
   — the canonical funnel, which dispatches `dispatch_provision`. First provision
   skips Spot (`SPOT_PLACEMENT_FALLBACK_S` is a 300 s wait a cold install does not
   need).
5. `refresh_task_definition(owner, secrets=+SLACK_BOT_TOKEN_{TEAM})`; wait
   PRIMARY; `patch_openclaw_config` with the account block + Friday binding —
   for a cold install this runs as a post-provision hook after step 0 of
   `provision_runner.py` has minted Friday's agent id (`channels` is otherwise
   reprovision-durable via §3.4). First-ever channel enable is a gateway
   restart deferred up to ~300 s; reuse `awaitChannelReady`.
6. `chat.postMessage` DM to the installer with the bot token: "Setting Friday up
   — I'll message you here in a couple of minutes." Second DM on
   provision-complete, carrying a sign-in-token link (`desktop_auth` pattern) so
   their first web visit is already signed in.
7. Redirect the browser to a "you're set — check your Slack DMs" page.

**Provisioning window.** Events arriving while `containers.status != running`
get 503 → Slack retries at +1 min / +5 min. A cold provision is 1.5–3 min best
case, so most first messages land on retry #2 or #3; anything beyond 5 min is
lost. `# ponytail: rely on Slack's retry for the provisioning window; add a
DDB stash-and-replay row keyed on owner if loss is observed.`

**Uninstall.** `app_uninstalled` / `tokens_revoked` arrive at the events URL with
`team_id`: row → `revoked`; `integration_secret_store.delete`;
`delete_openclaw_config_path(["channels","slack","accounts",team])` +
`remove_from_openclaw_config_list(["bindings"], accountId==team)` +
`channel_link_repo.sweep_by_owner_provider_agent` — `admin_delete_bot`'s body
(`routers/channels.py:265-290`) extracted to take an account id. Container keeps
running; Clerk org and billing untouched.

**Account wipe.** `account_wipe.py` already sweeps the owner's Secrets Manager
prefix and `integrations` rows; add one `WipeStep` for
`slack_installs.delete_all_for_owner`, calling Slack `apps.uninstall` best-effort
first so the workspace does not keep a dead install.

**Failure matrix.** Install ok / provisioning fails → row stays, SFN retries, DM
on terminal failure; retry is a reinstall. Uninstall mid-provision → mark revoked,
let provisioning finish (killing an in-flight claim is the EFS-WAL hazard), box
parks. Same workspace installs twice → §3.3 conditional put.

### 3.6 Onboarding — resolving the org

Join key: the installer's email.

| installer state | resolution |
|---|---|
| No Lightbulb account | `clerk_admin.create_user(email, skip_password_requirement, external_id="slack:{team}:{user}")` → `create_organization(name=team.name, created_by=user_id)` (installer becomes admin). Both ~40 lines mirroring `create_organization_invitation`. Write `users` row directly (do not rely on the `user.created` webhook). |
| Signed in, org context (`state.owner_id` is `org_…`) | Bind to that org. |
| Signed in, personal context | Create an org named after the workspace; new container. Personal container untouched. |
| Not signed in, has account | `find_user_by_email` → orgs the user admins that have **no** Slack install: 0 → create; 1 → bind; >1 → redirect to a "which team?" page reached via sign-in token. |
| Same workspace, reinstall | Same org → rotate token. Different org → 409 "already connected to *X*" unless revoked. |
| Same person, second workspace | New org. |

`# ponytail: one trial per Slack-minted org; dedupe on installer email if
trial-farming via throwaway workspaces is observed.`

### 3.7 Free tier + wake

- `ensure_personal_trial_default` (`user_provision.py:84`) and
  `_team_billing_required_gate` (`provision_gate.py:197`): admit an org whose
  billing row carries `origin: "slack"` (stamped at callback step 4). No other
  gate site changes; the seven autonomy sites keep refusing `trial_local`.
- Events path writes config through the internal patcher, so
  `routers/config.py:151` (`channels_require_subscription`) is untouched.
- Wake: step 7 of §3.1 calls `start_user_service` (which already enforces cap and
  expiry via `_assert_start_allowed`). Trial park (`_maybe_stop_trial_container`)
  stays as-is; a Slack-only owner cold-wakes on the first DM after idle (~40 s +
  retry at +1 min). Blocked owners (`trial_block_reason`) get a templated
  "upgrade" reply like `ses_inbound.py:288-297`, then 200 + `x-slack-no-retry`.

### 3.8 Migration

`mode` resolves per account, so a legacy socket account keyed by agent id and a
new http account keyed by team id coexist in one container, and the reprovision
re-injection copies both. Ship the OAuth tile as the default Slack path; demote
the wizard's Slack branch to "advanced"; on an owner's first successful shared-app
install, offer to remove their legacy account. No hard cutover.

## 4. Manifest

Built from what ships, each scope with a feature-linked justification:

- **Scopes (bot):** `app_mentions:read chat:write channels:history channels:read
  groups:history groups:read im:history im:read im:write mpim:history mpim:read
  mpim:write users:read files:read files:write reactions:read reactions:write
  commands assistant:write` (+ `pins:*`, `emoji:read`, `usergroups:read` only
  if the corresponding agent actions stay enabled; `chat:write.customize` when
  agent faces ship). **User scopes:** none. Installer identity via Sign in with
  Slack `openid email`.
- **Events:** `message.{channels,groups,im,mpim} app_mention reaction_added
  reaction_removed member_joined_channel member_left_channel channel_rename
  app_home_opened app_context_changed assistant_thread_started
  assistant_thread_context_changed app_uninstalled tokens_revoked`.
- **Features:** `bot_user`, `app_home {home_tab, messages_tab, read_only:false}`,
  `agent_view {description, suggested_prompts}`, `slash_commands: [/lightbulb]`
  with `url`, `shortcuts` (message: "Ask Friday about this"; global: "Ask Friday").
- **Settings:** `event_subscriptions.request_url`, `interactivity.is_enabled +
  request_url + message_menu_options_url` — **all the same URL**;
  `socket_mode_enabled: false`; `org_deploy_enabled: false`; `token_rotation_enabled:
  false`.

`slackManifest.ts` becomes this app's config, not a paste target.
