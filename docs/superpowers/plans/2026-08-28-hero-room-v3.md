# Hero Room v3 — Implementation Plan (Tasks 15–17)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The laptop fills the hero, lid always open, and the hero's copy is rendered on its screen as real DOM in perspective — typed on the laptop.

**Architecture:** `HeroFunnel` builds the copy once and passes it to `HeroLamp` as `screen`; `HeroLamp` renders it flat (server/no-JS/fallback/narrow) or hands it through `Scene` to `Laptop`, which mounts it in drei `<Html transform>` portalled into a non-aria-hidden sibling of the canvas. A head-script attribute (`data-lb-3d`) hides the flat copy before first paint for visitors who will get the 3D version, so there is no flash. Lid choreography and the idea texture are deleted.

**Tech Stack:** as before; drei `Html` (installed).

**Spec:** `docs/superpowers/specs/2026-08-28-hero-room-v3-addendum.md`.

**Worktree / branch:** `.worktrees/brand-visual`, `feat/hero-lamp-three`, HEAD `1731a6772`. Paths relative to `apps/frontend/`.

## Global Constraints

- Everything from the v1/v2 constraints still binds (contract, yellow-is-light, one lamp, colours from vars except the laptop's hex, 0 fps at rest, "Lightbulb" copy, self-hosted assets).
- The copy exists as ONE React instance; never two inputs in the DOM.
- The in-screen DOM must be focusable/typeable and visible to assistive tech (portal outside the `aria-hidden` canvas host).
- No flash of flat copy for 3D visitors; flat copy visible for no-JS, fallback, narrow.
- Constraints for framing at 1440×900 and 1280×720: screen 60–70% of viewport width; lamp glass fully visible above the screen top with ≥ 0.3 clearance at rest; desk front edge visible; no copy clipped.
- Commit per task; eslint + tsc clean before each commit; stage by name; no `git stash`.
