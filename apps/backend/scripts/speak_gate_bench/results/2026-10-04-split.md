`python -m scripts.speak_gate_bench.split`: spoken Live lines that name several agents (`split.jsonl`),
run through the real `messaging.address(live=True)` against live Jev on the dev gateway. A row passes when
exactly the expected agents are addressed and each agent's task holds the phrases it must and none it
must not.

What the rule cut got wrong: every line where the name comes AFTER its request (`name-last` 0/8).
"Can you check the deploy, Forge? And Friday, can you draft the customer email?" gave Forge the email.

The six lines added for the last row are the cases an independent review found by probing: a possessive
name ("Forge's PR"), numbers with periods ("v2.1", "3.5 percent"), a person's name after an agent's
part, a relayer and the agent it relays to, and real words at the end of a part ("say hello").

Known miss (every run): `first-04` "Friday what's on my calendar today, Forge is the staging server up?".
Jev labels Forge as talked about, not spoken to, so only Friday answers. A labelling miss, not a cut miss.

## Latency, and what it does to the score

- The question shape does not matter. Old and new shapes, 20 calls each, interleaved in the same
  minutes: p50 514 vs 562 ms, and 3 of 20 over 2 s for both.
- Jev's tail moves a lot. Over one evening the median of a run ranged from 295 ms to 1718 ms. The slow
  runs came right after heavy bench traffic (several hundred calls in the hour), which production does
  not have, so they may be throttling of this bench rather than Jev's normal state. Not proven either way.
- A call over the 2 s limit falls back to "every agent gets the whole line". In the slowest run 89 of
  126 calls did. So the feature degrades to today's behaviour when Jev is slow; it does not break.
- The hedge (a second identical call after 0.7 s) took a run from 21/72 timeouts to 0/108 an hour
  later. It cannot help when every call is slow.
- The gateway caches identical requests: repeat the same state and the timing is fake-fast.

Scores of runs with timeouts, for the record: 114/126 with 9 timeouts (112/117 of the answered ones
right, before the last possessive fix), and 47/126 with 89 timeouts.

Regression check: the 356-case multiparty bench (`--tag parts-v2`, before the review fixes) had 23
misses; chat classes A-D sat inside the ranges recorded in `2026-10-02-router-v2.md`.
