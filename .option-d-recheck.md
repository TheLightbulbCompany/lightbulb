## New findings

**Blockers: none.**

**I1 (Important): a steer into a *queued* call run is silently dropped.**
- `steer_run` stashes the text when the run has no agent yet, and returns True (turn:555-557).
- `attach_agent` hands the stash back (turn:143, :147).
- Room turns append it to the user message (turn:2437, :2448-2449).
- `_run_call` discards the return value (turn:266).

So under D's "follow-ups steer the run", a follow-up that lands while the call run waits on the session lock, the profile pull or agent construction (~13 s cold, per the turn:133 comment) gets a 202 and vanishes. D must also fold `attach_agent`'s return into `_run_call`'s input, alongside the `settle_steers` loop. The history file should then record the steered texts as user lines too.

**I2 (Important): a voice rename does not reach Hermes for any agent whose owner has saved its Instructions.**
- `refresh_agent_soul` says identity reaches a Hermes agent *only* through SOUL.md, and it skips an owner-edited SOUL.md (hermes_provisioning.py:1225-1233). §7 itself states the same rule as the reason voice notes left SOUL.md.
- Result: the voice persona (backend-built from the Paperclip name) says "Nova", while SOUL.md still says "Forge" on every room, call and Paperclip turn.

Fix inside D's own seam: inject the current name with `VOICE_NOTES.md` through `with_profile_agents_md`. For example, write the name into that backend-owned file, or a sibling one, as "Your current name is Nova". Do not rely on SOUL.md.

**Minor:**
- **m1.** Fix §9's API spelling (#15): `RoomOptions(audio_output=AudioOutputOptions(track_name=…))`. Also, with two concurrent RoomIOs the second one's `lk.chat` and pre-connect handlers are skipped with a warning, and the first one's close unregisters them by topic (room_io.py:96-104, :229; `_pre_connect_audio.py:50-61`). Pass `text_input=False` (the worker uses `generate_reply`, not `lk.chat`) and leave pre-connect audio off.
- **m2.** Fix the citations in #8 (`voice-live.ts:152-155`) and #43 (the memory plugin path). Reword #28 (`max_session_duration` recycles; it does not cap).
- **m3.** Window usage over budget: the overlap seconds summed per window are capped at `deadline - startedAt` (vc:200), so a switch-heavy window can under-bill. Either accept and state it, or extend the cap by the overlap.
- **m4.** An interim-transcript barge-in stops the floor-holder before the final confirms the name. If the final has no name, the floor-holder has been cut off for nothing. Say whether it resumes (a nudge) or the exchange ends.
- **m5.** Mark the 10 s binding window (see "Inferred-claim marking").
