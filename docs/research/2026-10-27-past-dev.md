# past.dev: a benchmarked memory API, and what it would mean to buy memory instead of building it (27 October 2026)

Read on 27 Oct 2026: past.dev (home, pricing, docs `llms.txt`, concepts, agent-setup prompt, blog "Introducing past.dev"), github.com/pastdotdev (16 repos: benchmarks, hermes-plugin, claude-code-plugin, codex-plugin, cursor-plugin, jetbrains-plugin, mcp, ai-sdk, llama-index, crewai, dify, n8n), the Hermes plugin catalog page, two PR Newswire releases (6 and 20 Oct), RuntimeWire's assessment, and the BEAM and DolphinBench papers via their vendors' pages. Markers: **[site]**, **[docs]**, **[repo]**, **[press]**, **[unverified]**.

## 1. What it is

"Long-term, multiplayer memory for agents." A hosted API: you send timestamped text (emails, transcripts, chats, tickets, documents) with an audience; it "derives the facts, rules, names and dated events"; `recall` returns ranked, dated evidence with sources, as of any date, for a named identity. No schema, embeddings or chunking on your side. **[site, docs]**

Company: Past AI, San Francisco, founded August 2025 by Mehdi Djabri (CEO; Lyft, Blackbird, co-founder of Iteration X) and Alex Ronse (CTO); backers named as General Catalyst, Varsity and Connect Ventures, no round size disclosed; launched by press release 6 Oct 2026 after a 30 Sep blog post; no named customers. SOC 2 Type II, ISO 27001, ISO 27701 on the site. **[press, site]** The founders say the API came out of agents they built for product, engineering, email and meeting work. **[press]**

## 2. How it works, as documented

| Aspect | Fact | Source |
|---|---|---|
| Ingest | `POST /api/v1/ingest` (and `/ingest/batch`, 1–1,000 data points, 16 MiB per request); one data point = one thing that happened, timed at its first message; conversation parts under 16,000 chars, documents under 32,000; async: poll `GET /ingest/{id}` until `completed`; `settled` means the whole project. "A recall sent too early finds nothing." | docs concepts, setup prompt |
| Recall | `POST /api/v1/recall` with `query`, `identity`, optional `queryTimestamp` (read memory as of a date), `occurredFrom`/`occurredTo`; returns `asOf`, `usedEvidenceTokens`, `results` (content, artifact context, dated sources, source record ids); `limit` 1–200 (default 100); evidence budget `level` low 8,000 / medium 16,000 / high 24,000 / extra-high 32,000 tokens; plan ceiling 8,000 on Pay-as-you-go and Flex, 32,000 on Enterprise | docs concepts, FAQ |
| Current state | Tracks current and previous values with dates and sources ("Acme budget is currently 40k", linked to the email that changed it); the earlier value stays readable as history; the mechanism is not disclosed | blog, site |
| Access control | Every data point belongs to an audience (a fixed list of identities or a rule over identity traits); every recall is made as one identity and sees only audiences that reach it; `identity` on a data point is the author, never the scope; "use separate projects for separate authorization domains" | docs access-control, FAQ |
| Deletion | Deleting data points (up to 1,000 ids per call) erases the memory derived from them; replacing a data point under the same id replaces its memory; deleting an audience makes its memory unreadable for good; deleting an identity keeps the memory | docs concepts |
| Auth | Bearer keys: an organization (management) key and project keys; "an agent token opens the memory routes for one person"; MCP at `https://app.past.dev/mcp` (Streamable HTTP + OAuth) with 56 console tools; a separate memory MCP for agents (`recall_memory`, `ingest_memory`, …) | docs, setup prompt |
| Rate limits | 500 / 750 / 1,000 requests per minute per key by plan; webhooks 20 per project (Flex and up) | docs concepts |
| Retention | Data 365 days (PAYG), 3 years (Flex), unlimited (Enterprise); request-log payloads 7 / 90 days / unlimited | pricing |
| Deployment | Managed; Enterprise "bring your own cloud: past.dev runs with your own AWS, Google Cloud or Azure account, operated by us", database-only or full | site, pricing |
| Training | Blog: no customer data used for model training; the pricing page says nothing | blog **[site]** |
| Internals | Not disclosed: no model names, storage, embedding or ranking method anywhere public | blog |

## 3. Integrations that matter to us

- **Hermes Agent memory provider** (`pastdotdev` v0.2.0, MIT, requires Hermes ≥ 0.21.0; our image reports 0.21.3). Recall before each message (the user's message, secrets stripped, as the query; injected as background; also a `past_recall` tool); `on_session_end` sends the session's user and assistant text, tool calls excluded; sessions kept in `~/.past/hermes/` until sent; cron runs, subagents and memory flushes never sent; messaging-gateway sessions off by default because "past recalls as one identity". Config: `PAST_API_KEY`, `PAST_IDENTITY`, `PAST_API_URL` (self-hosted past), `~/.past/config.json` shared with the Claude Code and Codex plugins; `"recall": false`, `"ingest": false`, `"gateway": true`. Install: `pip install "git+https://github.com/pastdotdev/hermes-plugin"`, `hermes config set memory.provider pastdotdev`. **[Hermes catalog]** It implements the same `MemoryProvider` seam our AgentCore plugin does (`initialize`, `prefetch`, `sync_turn`, `get_tool_schemas`), which our bridge selects with `memory.provider`.
- **Claude Code, Codex, Cursor and JetBrains (Junie) plugins**: "turns sessions into memory and briefs each new session" (updated 22 Oct; 0 stars each). This is Beacon's capture-and-recall loop for coding sessions, already built against this API. Not read in depth. **[repo, unverified beyond the descriptions]**
- Also: MCP servers, Vercel AI SDK, LlamaIndex, CrewAI, Dify, n8n.

## 4. Benchmarks, and how they were produced

Everything below is the vendor's own run, published with a harness that uses only the public API (`github.com/pastdotdev/benchmarks`, MIT, 4 stars). That is more than any competitor in our set publishes (Beacon: nothing; Mem0, Hindsight, Honcho, Exabase: their own blogs).

**BEAM** (ICLR 2026 paper "Beyond a Million Tokens": 100 conversations, 2,000 questions, 100K to 10M tokens, ten memory abilities incl. contradiction and event ordering).

| Split | Conversations | Questions | past.dev | Hindsight | Exabase M-1 | Honcho | Mem0 |
|---|---|---|---|---|---|---|---|
| 100K | 20 | 400 | 92.08% | 86.2% | 76.9% | 63.0% | — |
| 500K | 35 | 700 | 89.63% | 80.1% | — | 64.9% | — |
| 1M | 35 | 700 | 90.65% | 79.1% | 75.0% | 63.1% | 64.1% |
| 10M | 10 | 200 | 85.03% | 64.1% | 68.0% | 40.6% | 48.6% |
| Combined | 100 | 2,000 | 90.02% | | | | |

Method (their `beam/README`): one model, `openai/gpt-5.6-luna` via OpenRouter with reasoning off, answers and judges; ExaBase's published BEAM prompts unchanged (`verify.py --prompts` checks them by SHA-256); each conversation is its own project; turns ingested in batches of 100 at noon UTC on their session day, one microsecond apart; the harness waits for `completed` and `settled`; each question recalls at its `queryTimestamp`, up to 100 results within 8,000 tokens; each question answered once. Cost not stated; the 10M split "takes hours". Competitor numbers are each vendor's own, from different models and judges ("uneven comparison setups", RuntimeWire). **[repo, press]**

**DolphinBench** (Mem0's benchmark: 600 tasks over three personas with ~500K-token histories, graded on the app calls the agent makes; Mem0's own best: 70.67% with Hermes + GPT-5.6 Luna).

| Run | Passed | Cost | Median latency | Notes |
|---|---|---|---|---|
| Hermes Agent + GPT-5.6 Luna + past.dev memory | 490/600 (81.7%, 95% CI 78.4–84.6) | $196.72 | 51.6 s | several passes over the same memory; toolsets changed between passes; one test passed via web search (489 without) |
| past.dev's minimal agent (`past_harness.py`, tool loop, ≤60 turns, high reasoning) + the same model | 520/600 (86.7%, CI 83.7–89.2) | $15.77 | 9.8 s | ingest stored only the user's messages; recall as a system message plus `past_recall` |

Judge: GPT-5.6 Sol, medium reasoning, DolphinBench's fixed settings, pinned to one provider. Disclosed variance: rerunning 400 tests changed 69 outcomes. The press release calls 490 "the highest result published" and "not an official score". **[repo, press]**

**What this tells us.** (1) past.dev is the only memory vendor in our set whose numbers a third party can rerun against the public API, with the judge prompts pinned. (2) The comparison table is still apples to pears; a fair claim is "top of the published BEAM numbers under our own run". (3) The Hermes harness scored five points lower and cost twelve times more than a sixty-line tool loop with the same model and the same memory. Our workspace agents run on Hermes; the harness, not the memory, is where the cost and the latency sit.

**Can we get better numbers?** Not on BEAM or DolphinBench by building our own recall; those are the memory vendors' home ground and past.dev's 90% took a team a year. The numbers nobody publishes are the team ones in `2026-10-27-memory-decision.md` §5 (memory that crosses people, repeated-question rate, review without a third party, bytes leaving the laptop), because every vendor here is single-identity or single-project at the product level even when the API is "multiplayer".

## 5. Price, and what a Lightbulb workspace would cost

Plans **[pricing]**: Pay as you go $0 (150,000 credits to start, 400,000 with a work email; 1 project; 500 rpm; 8,000-token recall); Flex $99/month (400,000 credits, 5 projects, 750 rpm, webhooks, 3-year retention); Enterprise custom (from 5,000,000 credits/month, unlimited projects, 32,000-token recall, SSO/SAML, bring-your-own-cloud, "custom retrieval arms, entity type and edge customization"). Top-ups $0.30 per 1,000 credits at 100,000, down to $0.13 at 10,000,000. A credit = 350 bytes ingested (minimum one per data point); one credit per recall on Pay as you go, unlimited recall within fair use on Flex and Enterprise.

Sketch for one active workspace per month (assumptions stated, to be measured): 3,000 room and DM messages at ~400 bytes ≈ 3,500 credits; 3,000 agent turns recalling once ≈ 3,000 credits (PAYG only); 200 laptop sessions at ~50 KB ingested ≈ 29,000 credits. About 35,000 credits ≈ $10 at the smallest top-up, or a tenth of Flex. Ten workspaces fit inside Flex's 400,000 credits if sessions are summarized before ingest, and not if they are sent raw. AgentCore today: $0.75 per 1,000 records a month plus $0.50 per 1,000 retrievals, records accumulating, per-workspace spend unmeasured (inventory §3).

Tenancy: their rule is one project per authorization domain. One project per workspace means Enterprise (Flex allows five). The alternative, one project with an audience per workspace and an identity per member, is enforced server-side by identity, but it is not what their docs recommend. This is the first question to put to them.

## 6. What is unverified

Customers and production scale (none named; RuntimeWire flags it); the round size; the internals (models, storage, ranking); the Claude Code and Codex plugins' behaviour beyond their one-line descriptions; the startup program (six months of Flex free, reported by the search summary, absent from the pricing page); SLAs and data residency outside bring-your-own-cloud; whether per-identity agent tokens are available on every plan.

## 7. Fit with Lightbulb

What maps directly:

| Lightbulb | past.dev |
|---|---|
| Workspace | project (or audience) |
| Room, DM | audience (fixed list of members and agents); a private DM scope = audience of two |
| Member or agent | identity, with traits (role, team) for rule-based audiences |
| "Share with the team" after an approval card | re-ingest the lesson into the team audience with the approval as its source |
| Memory tab (list, delete, share, confirm) | recall with sources; delete by data-point id; provenance is native (dated sources, previous values) |
| Hermes agents in rooms | the `pastdotdev` MemoryProvider on the seam our AgentCore plugin already uses |
| Laptop sessions on the network (Claude Code, Codex, Cursor) | their plugins do capture-and-brief today; ours would ingest from our hooks under the person's identity so the network stays one install |
| "As of" questions ("what was the plan before Tuesday") | `queryTimestamp` |

What it gives us that AgentCore does not: current-versus-previous values, dated sources on every answer, identity-aware audiences instead of IAM-plus-convention, deletion that erases derived memory, a published benchmark and harness, a bring-your-own-cloud path, and a vendor whose whole company is this problem.

What it costs us: a second vendor in the data path (Clerk, AWS, OpenRouter, Stripe, Metronome, PostHog today), workspace content leaving our AWS account below Enterprise, async ingestion (seconds to minutes before a fact is recallable), the 8,000-token recall ceiling below Enterprise, early-stage risk (fourteen months old, no named customers), and the tenancy question above.

## 8. Recommendation: buy the recall, build the room

The memory decision's phase 0 proposed building personal memory in the engine (SQLite FTS5, our own distill step). past.dev changes that calculus for the cloud tiers: recall quality is their whole business and is benchmarked; ours would start at Beacon's level. The honest split:

- **Build what is ours.** The network transport, the hooks that capture a session on the laptop, the distill prompt at session end (the agent drafts the lesson), the approval card that turns a lesson into team memory, the Memory tab with provenance, the audiences derived from rooms, the deletion that follows a member leaving, and the team metrics nobody else publishes.
- **Buy the recall.** past.dev behind our existing `MemoryProvider` seam for the workspace, and behind the account for signed-in laptops. Keep AgentCore as the fallback provider until a cost read and a one-workspace pilot say otherwise; the switch is configuration, not a rewrite.
- **Keep the free, no-account tier honest and thin.** Messaging and local capture only. Memory arrives with sign-in, which is the consent moment, and which makes the "nothing leaves your machine until you sign in" line exactly true.
- **Before committing:** a two-week pilot on one workspace (ours), measuring recall hits per turn, latency to recallable, credits per workspace, and the tenancy answer from past.dev. Ask them about per-identity agent tokens, one-project-per-workspace pricing below Enterprise, and bring-your-own-cloud in our AWS account.
