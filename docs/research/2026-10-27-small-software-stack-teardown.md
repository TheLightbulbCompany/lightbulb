# The stack behind "an agent builds a small app": Lovable and peers, from the docs

All sources fetched 2026-10-27. Tags: **[P]** vendor docs or pricing page, **[S]** vendor marketing or third party, **[U]** could not verify.

## 12-line summary

1. Lovable stack: React + TypeScript + Tailwind + shadcn/ui on the screen; projects created since 13 May 2026 use TanStack Start (server-rendered), older ones React + Vite; the backend is "Lovable Cloud" (built on Supabase's open-source foundation: Postgres, auth, file storage, edge functions) or a Supabase project you own.
2. While you edit, the app runs in "a temporary cloud environment that Lovable starts for your project"; preview and published app share one backend and one database.
3. Publish deploys a snapshot to `<name>.lovable.app` on Lovable's own hosting with HTTPS; later edits go live only after "Publish changes".
4. Backend ownership: with Lovable Cloud, Lovable runs the infrastructure and bills it in credits; the database export leaves out files, edge-function code and secrets, and there is no one-step move to your own Supabase. With your own Supabase, you own it and Supabase bills you.
5. Code ownership: you own the code; two-way Git sync on all plans, zip download on paid plans.
6. Money meter: build credits per message (0.5 to 2 credits typical) plus Run credits for database, compute, network, storage and AI; Pro $25 for 100 credits, Business $50 for 100; 20 Cloud + 4 AI credits granted monthly; at zero credits Cloud-backed apps pause.
7. Lovable vs Claude Artifacts, difference 1: Lovable has a backend (database, sign-in, server functions). An artifact "is a static page. It can't authenticate viewers itself": no backend, no database beyond 20 MB of text-only storage.
8. Difference 2: hosting and sharing. Lovable publishes to a public URL and bills traffic; artifacts live on claude.ai, most viewers need a Claude account, and the creator pays nothing when viewers' artifacts call Claude.
9. Difference 3: ownership and editing. Lovable leaves you a repo, versions, rollback and a code editor; an artifact is one HTML file republished as versions, with no repo unless you keep the file yourself.
10. A one-off tool can skip: backend, database, sign-in, hosting, domain, deployment pipeline. It is one file with its data baked in, and "who can open the file" is its only permission.
11. The moment it needs live data, two users, or to run again next month, you need: a data source, sign-in plus row rules, a server function or scheduled job, hosting with a URL, versions, and a bill for compute and storage.
12. The rest: Bolt runs the dev environment inside the browser tab (WebContainers); Replit runs it on Google Cloud with usage-billed deployments; Base44 is a managed NoSQL backend with single-page-app hosting; v0 outputs Next.js and deploys to Vercel; Claude Code and Codex write files on your machine and leave hosting to you.

## 1. Anatomy of a small app, in plain words

- **Screen (frontend).** What people see and click, running in their browser. Example: the form and the table in an expense tracker.
- **Logic (backend / server functions).** Code that must run somewhere other than the viewer's browser, usually because it holds a secret or talks to another service; Lovable calls these edge functions, "the work that can't happen in the user's browser" (https://docs.lovable.dev/features/edge-functions, 2026-10-27). Example: sending an email, or calling an AI model with a hidden key.
- **Data (database, storage/files).** A database holds structured records (rows in tables); file storage holds uploads such as PDFs and images. Example: one row per expense; the receipt photo in a storage "bucket".
- **Sign-in and permissions (auth, row-level security).** Auth is how the app knows who you are. Row-level security (RLS) is a database rule that acts "like a `WHERE` clause added to every query on the table", so each person sees only their rows (https://supabase.com/docs/guides/database/postgres/row-level-security, 2026-10-27). Example: Priya sees only Priya's expenses.
- **A place to run (hosting, URL, domain).** A server that serves the screen and runs the logic, reachable at an address. Example: `expenses.lovable.app` or `expenses.yourcompany.com`.
- **A way to change it (editing, versions, rollback).** Each change saved as a version you can inspect or return to. Example: undo yesterday's broken edit.
- **A way to share it (links, team access).** Who may open, edit or publish it. Example: five colleagues can open it, two can edit.
- **The money meter.** Two streams almost everywhere: credits or tokens for the agent's building work, and usage for running the app (database size and uptime, data transferred, storage, AI calls the app makes).

## 2. Lovable, end to end

**Prompt and agent.** Build mode (formerly Agent mode) is the default and "takes ownership of execution end to end"; Plan mode writes "a plan you edit and approve before building" at "one credit, plus the cost of any subagent research"; Chat mode discusses without changing code. Build mode "can observe build errors and failures from test runs" and "reproduce reported issues with browser testing or targeted backend calls", but "Most of these tools run only when you ask for them"; one message can run up to 10 hours (https://docs.lovable.dev/features/modes, 2026-10-27) [P]. Lovable "uses current leading AI models and updates them for everyone automatically" and does not name the builder models (https://docs.lovable.dev/introduction/faq, 2026-10-27) [P].

**Live preview.** It runs in "a temporary cloud environment that Lovable starts for your project while you work"; preview links open "with no Lovable account needed" and expire after 7 days on Free and Pro; preview and published app "share the same backend and data" (https://docs.lovable.dev/features/projects/preview, 2026-10-27) [P].

**The code.** Apps created from 13 May 2026 (22 June for Enterprise) use TanStack Start, which "renders pages on the server"; older apps use React + Vite and "render in the browser"; the database is PostgreSQL; you own the code "subject to third-party rights such as open-source licenses" (FAQ, above) [P]. Lovable's guide names "React with Vite, TypeScript, Tailwind CSS, shadcn/ui, and a Supabase backend" and states "Lovable generates React with Vite, not Next.js" (https://lovable.dev/guides/lovable-vs-vercel-platform-comparison-guide, 2026-10-27) [S].

**Backend A: Lovable Cloud.** The built-in backend "uses Supabase's open-source foundation": database, realtime, authentication, storage, edge functions; enabling any of database, user accounts or file storage "provisions all three"; the region locks once enabled; agent permissions default to Always allow except "Execute backward incompatible database migrations" (Never allow) (https://docs.lovable.dev/features/cloud, 2026-10-27) [P].
- *Tables and RLS.* "Lovable sets up these rules automatically when it builds features that store user data"; the policies view is read-only and you change a policy by asking in chat (https://docs.lovable.dev/features/database-access, 2026-10-27) [P]. The docs never say RLS is on for every new table [U]. Supabase's rule: a table "without RLS is readable and writable by any role with a grant on it"; "Once RLS is enabled, no data is accessible through the API ... until you create policies" (Supabase RLS page, above) [P].
- *Storage.* Buckets are "Private" by default and public buckets are "blocked by default on all plans"; uploads 2 GB by default, up to 5 GB (https://docs.lovable.dev/features/storage, 2026-10-27) [P].
- *Edge functions.* Run "on Lovable's servers" and "scale automatically with traffic"; the agent writes and deploys them; runtime and language are not named [U] (edge-functions page, above) [P].
- *Auth.* Default is email + password, Google and "Sign in with Lovable"; Google, Apple and Microsoft work "Managed by Lovable" with no credentials; SAML 2.0 and OIDC supported; adding login "protects user data with row level security" (https://docs.lovable.dev/features/authentication, 2026-10-27) [P].
- *Security scanner.* A Quick scan runs on every publish (tables without RLS, permissive rules, storage rules, leaked-password protection off, dependency audit); a Deep scan reviews all code on demand; admins can enable "Block publishing with critical issues"; 10 free fixes renew after 24 hours (https://docs.lovable.dev/features/security, 2026-10-27) [P]. No feature named "Shield" appears in the docs [U].
- *AI gateway for apps.* A `LOVABLE_API_KEY` is issued per project; "AI calls run through a secure backend function that Lovable creates for you"; the model list spans OpenAI, Google Gemini and Anthropic Claude families; the connector "cannot use your own provider API key"; out of credits returns `402 Payment Required` (https://docs.lovable.dev/features/ai, 2026-10-27) [P].

**Backend B: your own Supabase.** The integration "connects a Supabase project you own" and "is available on all plans"; migrations are approved in chat and saved under `supabase/migrations/`; "Authentication settings themselves live in your Supabase project, not in Lovable"; Supabase bills usage; switching "is not automatic in either direction"; managed backups, managed Google auth, SAML SSO and signed-in browser testing need the built-in backend (https://docs.lovable.dev/integrations/supabase, 2026-10-27) [P]. Supabase Free: 500 MB database, 1 GB storage, 5 GB egress, 500,000 edge invocations, 2 active projects, "paused after 1 week of inactivity"; Pro from $25/month (https://supabase.com/pricing, 2026-10-27) [P].

**Publishing.** "Lovable hosts the published app for you: no servers to set up, and HTTPS included"; "Only the current version is deployed"; default address `[url-subdomain].lovable.app`; publishing from the dialog "is free, even with a zero credit balance", asking the chat to publish costs credits; "Hosting the app and running its built-in backend consume Run credits"; Free projects may be unpublished after 12 months with no visits (https://docs.lovable.dev/features/deploy, 2026-10-27) [P]. Custom domains are "available on paid plans"; the A record points to `185.158.133.1`; SSL is automatic; "there is no way to remove the `xxx.lovable.app` project URL" (https://docs.lovable.dev/features/custom-domain, 2026-10-27) [P]. Publishing only to invited people: 10 per project on Free and Pro, unlimited on Business and Enterprise (https://docs.lovable.dev/introduction/subscription-plans, 2026-10-27) [P].

**GitHub sync.** "two-way sync"; the repository is created under the account or organization you pick, "private by default"; "Lovable only edits and syncs one branch at a time"; on disconnect "Your repository stays on GitHub" and "Your project and its code stay in Lovable"; reconnecting "creates a new repository" (https://docs.lovable.dev/integrations/github, 2026-10-27) [P]. GitLab and Bitbucket also sync, on any plan (FAQ) [P].

**Editing after launch.** The preview toolbar (which replaces Visual Edits) offers element selection, inline text edits (100 free per account, renewing after 24 hours), drawn annotations and pinned comments; select and draw requests cost credits (https://docs.lovable.dev/features/visual-edit, 2026-10-27) [P]. Code editor: "Code editing is available on paid plans", "Editing and saving code yourself doesn't use credits", "Each save becomes a version", "Lovable doesn't review your manual edits" (https://docs.lovable.dev/features/code-mode, 2026-10-27) [P]. History: "Every change Lovable makes to your project creates a version automatically"; revert restores "code only" and "does not restore or roll back database data"; bookmarks mark stable versions; very old versions preview only (https://docs.lovable.dev/features/projects/history, 2026-10-27) [P].

**Sharing and team.** Project roles Viewer, Editor, Admin, Owner; editors and above publish; collaborators "use credits from the project owner's workspace"; each works in their own draft (https://docs.lovable.dev/features/collaboration, 2026-10-27) [P]. "Unlimited workspace members on all plans"; SSO and role-based access from Business (subscription-plans page) [P]. For internal apps, Business and Enterprise projects on TanStack Start can reuse the signed-in Lovable identity so "teammates don't need a separate login"; only people "logged in to Lovable and have access to the project" are recognized (https://docs.lovable.dev/features/lovable-workspace-identity-reuse, 2026-10-27) [P]. Enterprise Organizations let "members of every workspace in the organization ... open an app after logging in"; "Lovable sets up organizations on request"; "no shared credit pool" (https://docs.lovable.dev/features/organizations, 2026-10-27) [P].

**Credits and pricing.** Pro: 100 credits $25/month to 10,000 credits $2,250/month; Business: 100 credits $50/month to 10,000 credits $4,300/month; annual billing "gives two months free" (subscription-plans page) [P]. Free: 5 daily build credits capped at 30/month; Pro and Business: 5 daily, uncapped; all get a 20-credit Cloud grant, 4-credit AI grant and 1-credit connector grant monthly, none rolling over; plan credits roll over while active and expire 2 months after issue; top-ups expire after 12 months; Build examples: button colour 0.50, add authentication 1.20, landing page with images 2.00 credits (https://docs.lovable.dev/introduction/plans-and-credits, 2026-10-27) [P]. Run credits cover "database server, database storage, network, storage, compute, and realtime" plus AI; a bigger instance "uses more credits per hour while your app runs"; stored files keep using credits while paused; at zero credits "building stops, AI features in deployed apps stop working, and apps that use the built-in backend (Cloud) pause" (https://docs.lovable.dev/features/project-usage and https://docs.lovable.dev/user-guides/credits, 2026-10-27) [P]. On cancel "Your current plan remains active until the end of the current billing period", then Free; connected custom domains keep serving (plans-and-credits; deploy page) [P].

**What you leave with.** Code via Git sync (any plan) or zip (paid). Data via "Export project data", which "does not include stored files, Edge Function code, or secrets"; files download separately (FAQ; storage page) [P]. Removing the database "permanently deletes the database, its backups, your app's user accounts, and the files in storage"; "Lovable does not move a project to your own Supabase in one step" (cloud page) [P]. The hosted app stays on Lovable; elsewhere you rebuild from the repo.

## 3. The same trace, briefly, for the others

**Bolt.new.** "Bolt runs on WebContainers ... a browser-based technology built by StackBlitz that runs a full development environment directly in your browser" (https://support.bolt.new/concepts/faq, 2026-10-27) [P]. WebContainers run Node.js "entirely inside your browser tab", so "compute happens locally, so there are no per-minute cloud VM costs" (https://webcontainers.io/guides/introduction, 2026-10-27) [P]; desktop Chromium only out of the box, Safari beta, Firefox alpha (https://webcontainers.io/guides/browser-support, 2026-10-27) [P]. "Bolt only supports JavaScript-based backends, so languages such as PHP or Python aren't compatible" (https://support.bolt.new/building/supported-technologies, 2026-10-27) [P]. Bolt Database is default on every plan; Supabase needs Pro or Teams; version restore "doesn't change your Supabase databases" (https://support.bolt.new/integrations/supabase, 2026-10-27) [P]. Publishing to bolt.host is free; Free is capped at 10 GB bandwidth and 333,333 requests a month, then the site goes offline for the month (FAQ) [P]; Netlify "can't host a database or a traditional backend" (https://support.bolt.new/integrations/netlify, 2026-10-27) [P]. Mobile: "Include the words `mobile app` in your first prompt" for Expo (FAQ) [P]. Free 1M tokens/month, 300K daily cap; Pro $25/month, 10M tokens, rollover, custom domain; Teams $30/member (https://bolt.new/pricing, 2026-10-27) [P].

**Replit.** The agent "takes action", "tests its own work on a regular basis" and "creates checkpoints as it works"; modes Free, Auto, Power, Max (https://docs.replit.com/replitai/agent, 2026-10-27) [P]. "effort-based pricing, based on request complexity", one checkpoint per request; Claude, ChatGPT and Gemini calls are billed "at the provider's public API rate and deducted from credits" (https://docs.replit.com/billing/ai-billing, 2026-10-27) [P]. Core $20/month with "$20 towards more powerful models"; Pro $100/month (https://replit.com/pricing, 2026-10-27) [P]. Workspace: "a reusable image with the repository, runtime, tools, and dependencies" (https://docs.replit.com/build/code/create-reusable-environment.md, 2026-10-27) [P]; Nix is no longer named in the docs index [U]. Data: "a fully-managed PostgresSQL database" billed for compute time and storage; App Storage "Backed by Google Cloud Storage" (https://docs.replit.com/learn/projects-and-artifacts/storage-and-databases.md, 2026-10-27) [P]; 20 GB free storage per app; "Time travel" restores to any checkpoint (https://docs.replit.com/cloud-services/storage-and-databases/sql-database, 2026-10-27) [P]. Replit Auth is Agent-provisioned, Replit-branded, on "Replit's shared OAuth apps" (https://docs.replit.com/learn/projects-and-artifacts/auth.md, 2026-10-27) [P]. Publishing "saves a snapshot"; infrastructure "runs on Google Cloud Platform", US-hosted, one single-tenant GCP project per customer (https://docs.replit.com/learn/projects-and-artifacts/replit-deployments.md, 2026-10-27) [P]. Autoscale $2/month + $0.60 per million compute units + $0.40 per million requests; Reserved VM $15 to $130/month; Static free with $0.05/GB transfer; Scheduled $2/month (https://docs.replit.com/billing/deployment-pricing, 2026-10-27) [P].

**Base44.** "Backend-as-a-service built with AI agents in mind", backend and CLI "currently in beta" (https://docs.base44.com/developers/backend/overview/introduction, 2026-10-27) [P]. "a NoSQL database where you define your data models as entities", MongoDB-compatible; row-level and field-level security; auth by email/password, Google, Microsoft, Facebook, Apple, SSO; "Deno-based serverless functions" in TypeScript; built-in AI, file-upload and email integrations; "site hosting currently supports Single Page Applications (SPAs) only", custom domains, automatic HTTPS (https://docs.base44.com/developers/backend/overview/features, 2026-10-27) [P]. Pricing (annual): Free 25 message credits, 5 apps; Starter $16, Builder $40, Pro $80, Elite $160 per month; custom domain from Starter; "Two-way GitHub sync" from Builder; apps "run on real production infrastructure, not a sandbox" (https://base44.com/pricing, 2026-10-27) [P]. A third-party guide says `base44 eject` exports code and schemas but "creates a new backend with an empty database" and user password records do not export (https://www.13labs.au/guides/migrate-off-base44-to-production, 2026-10-27) [S]; not confirmed in Base44 docs [U].

**Vercel v0.** Next.js, React, TypeScript, Tailwind CSS, shadcn/ui; "Publish with one click on Vercel"; "v0 never pushes directly to main"; "Vercel doesn't own the code generated based on your queries and prompts"; "Export the code to work locally" (https://v0.app/docs/faqs, 2026-10-27) [P]. Free 7 messages/day; Plus $30/user/month with $30 credits plus $2 daily; Business $100/user/month; token-metered, e.g. v0 Pro model $2 in / $10 out per million tokens (https://v0.app/pricing, 2026-10-27) [P]. Vercel Hobby is free for "non-commercial, personal use only" with 100 GB fast data transfer and 1,000,000 function invocations; Pro seats $20/user/month (https://vercel.com/docs/plans/hobby, 2026-10-27) [P].

**Claude Artifacts and Claude-powered artifacts.** An artifact is "anything Claude makes for you that you'd put in front of someone"; storage "has a 20 MB limit per artifact", "accepts text only", personal or shared, on Pro, Max, Team and Enterprise; Claude-powered artifacts: "the app runs on Anthropic's infrastructure", "No API keys are required, and there's no cost to you", usage "counts against each person's own plan limits rather than yours" (https://support.claude.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them, 2026-10-27) [P]; announced 25 July 2025 (https://claude.com/blog/claude-powered-artifacts, 2026-10-27) [P]. Constraints: "An artifact is a static page. It can't authenticate viewers itself"; a strict CSP allows scripts only from five CDNs and fonts from Google, and `fetch` only to the page's own origin; "Relative links do not resolve"; 16 MiB maximum; pages load from a sandboxed `*.claudeusercontent.com` origin; connector-backed pages call MCP connectors "through the viewing account's own connection"; "For a hosted internal tool with a backend, deploy it on your own infrastructure instead" (https://code.claude.com/docs/en/artifacts, 2026-10-27) [P]. Sharing: "Artifacts start private"; Pro/Max choose "Only you" or "Anyone with the link"; Team/Enterprise stay in-organization unless external sharing is on; "People without [a Claude account] can't open a shared artifact, even with the link", except legacy chat-published artifacts; unpublishing "permanently deletes the personal and shared storage data" (https://support.claude.com/en/articles/9547008-publishing-and-sharing-artifacts, 2026-10-27) [P].

**Claude Code / Codex.** Claude Code "reads your codebase, edits files, runs commands" in terminal, IDE, desktop or browser, on a Claude subscription or Console account (https://code.claude.com/docs/en/overview, 2026-10-27) [P]; enterprise average "around $13 per developer per active day" (https://code.claude.com/docs/en/costs, 2026-10-27) [P]. Codex: local workflows "run on your device" in an OS-enforced sandbox with network off by default; cloud tasks run in "OpenAI-managed containers"; included in ChatGPT Plus, Pro, Business, Edu and Enterprise (https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan, 2026-10-27) [P]. Neither hosts anything: to put the result online you choose a host (e.g. Vercel Hobby, free non-commercial), a database (e.g. Supabase Free), add sign-in, a domain and a deploy step yourself, and pay each vendor separately.

## 5. One-off internal tool versus a recurring one

A **one-off** tool (a calculator for this week's pricing decision, a chart of last quarter, a form that produces text to paste elsewhere) needs only the screen. It can be a single HTML file: the data is a snapshot pasted in, the logic runs in the viewer's browser, and the only permission is who can open the file or link. That is the artifact model, "one self-contained page with no backend" (https://code.claude.com/docs/en/artifacts, 2026-10-27) [P]. It skips the backend, database, file storage, sign-in, RLS, hosting with a domain, a deploy pipeline and a running bill. It keeps only a way to edit it (republish or regenerate) and a way to share it (a link, under whatever account rule the host imposes).

The **recurring** parts appear at three thresholds, each visible in the docs above:

1. **Live data.** Once the tool must read today's numbers rather than a pasted snapshot, it needs a data source: a database the app owns (Lovable Cloud or Supabase, Replit Postgres, Base44 entities) or a connector called at view time (artifact connector calls run "through the viewing account's own connection", so every viewer needs that connection). A database brings storage and compute charges that continue when nobody is using the app ("Stored files keep using credits while a project is paused").
2. **Two people.** Once two users write to it, it needs sign-in and row rules so one person's rows are not served to another ("protects user data with row level security"), plus roles for who edits versus views. Shared state needs a home: 20 MB of text-only artifact storage at the small end, a real database above that.
3. **Run again next month.** Anything scheduled or triggered needs server-side logic (Lovable Jobs or edge functions, Replit Scheduled deployments at $2/month, Base44 Actors), a stable URL, secrets kept out of the code, versions to roll back to, and a security check before each publish. This is where hosting stops being free and the money meter splits into build cost and run cost.

In short: a one-off is a document that happens to be interactive; a recurring tool is a small product, and every vendor charges for the same five things once it crosses that line: database, compute, traffic, storage and AI calls.
