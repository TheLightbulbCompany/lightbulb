# Huddles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Channel huddles on LiveKit: people talk to each other, the CEO agent follows along and answers out loud when named or when someone holds Talk, and the team works behind it through the existing voice-call routing.

**Architecture:** Backend mints LiveKit tokens and dispatches one CEO worker (LiveKit Cloud Agents, Python) per huddle room. The worker transcribes each person, and on a summon opens a GPT-Live session with client delegation; delegations go to new internal backend routes that reuse `voice_calls` (gates, billing, routing, Hermes runs). Hermes run frames reach the worker through a backend relay that calls LiveKit `SendData`.

**Tech Stack:** FastAPI + DynamoDB (existing), `livekit-api` (backend), `livekit-agents[openai,silero]~=1.8` (worker), `livekit-client` + `@livekit/components-react` (web), Hermes bridge (Python), CDK.

**Spec:** `docs/superpowers/specs/2026-10-01-huddles-design.md`

## Global Constraints

- One voice: the CEO (`starter_agent_ids["ceo"]`); other agents never speak. Routing is `voice_routing.pick` unchanged (name → Jev → CEO).
- Summoned, never ambient: the worker's GPT-Live input is muted unless an exchange is open.
- LiveKit room name: `huddle-{env}-{roomId}`. CEO participant identity: `agent-ceo`. Worker agent name: `lightbulb-huddle`. Data topic for frames: `call.frame`. RPC methods: `talk_start`, `talk_end`.
- Internal worker auth header: `X-Lightbulb-Huddle-Secret`, compared with `hmac.compare_digest` against `settings.HUDDLE_WORKER_SECRET`; every internal route also checks the room's `ownerId`.
- Secrets: `lightbulb/{env}/livekit_api_key`, `lightbulb/{env}/livekit_api_secret`, `lightbulb/{env}/huddle_worker_secret`. Env: `LIVEKIT_URL`. Empty `LIVEKIT_URL` ⇒ huddle routes 503 `huddles_unavailable` (dark switch, like `openai_live.configured()`).
- Billing: a summon is a voice call row with `kind: "huddle"`; only GPT-Live seconds bill (worker-reported `usageSeconds`); STT and LiveKit minutes are EMF metrics only (`huddle.stt.seconds`, `huddle.agent.seconds`).
- A huddle leaves nothing behind: no transcript or recording is stored anywhere.
- Vendor shared-channel guests cannot join (404 `room_not_found`, same check as v2 `_room_team`).
- No live LiveKit needed for any task's tests: all LiveKit calls go through one backend module and one worker adapter that tests fake.
- Colours only from tokens (`brandTokens.test.ts`); no `any` in TS (eslint error); targeted tests only, CI is the full gate.

## Review Focus

- A summon while another exchange is open in the same huddle → the new speaker takes over (set_participant), no second GPT-Live session or call row. (Task 8 test.)
- The worker crashes or LiveKit drops it mid-exchange → the call row still closes and bills via the existing sweeper (deadline), and the next join re-dispatches a worker. (Task 3 test: join dispatches when no `agent-ceo` participant.)
- Last human leaves while the CEO is answering → exchange ends, `/end` posts, worker exits. (Task 8 test.)
- Free-tier workspace with another free call open (v2 one-free-call rule) → summon refused with `voice_busy`; worker says so in plain words, huddle continues. (Task 2 + Task 8 tests.)
- Frames for a superseded turn arriving late → dropped (turnId mismatch), never spoken. (Task 7 test.)
