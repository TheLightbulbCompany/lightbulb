## Verdict up front

- I found **no further React crash** on the Go-live path. Every hook in `HuddleBar` that needs a participant now
  gets one. `useTracks`, `useMultibandTrackVolume`, `useParticipantAttributes` and `RoomAudioRenderer` all hold up
  with no Lightbulb in the room (details under "Web hooks verified").
- The next failures the owner will hit are **broken flows, not crashes**: Lightbulb never answering (finding 1, if
  runtimes weren't rolled), hold-to-talk silently doing nothing (findings 3 and 4), and a dead participant STT loop
  after any GPT-Live session failure (finding 5).
- **PR #3543 cannot crash the page.** It only touches the worker, and the prod worker deploy is
  `workflow_dispatch`-only (`.github/workflows/huddle-agent.yml:45-47`), so a merge ships nothing to prod. It is
  not ready to *ship*: its cut-in triggers on "Thank you." and on side remarks (finding 13), and it double-feeds the
  cutter's request (finding 14). Fix those two before the prod dispatch.

## Findings

Severity: Critical = crash or blocks the feature; Important; Minor.

### Main

1. **Critical (deployment precondition, unverified): Lightbulb never speaks on a runtime that isn't rolled to `h-2026.10.1-e3f0e1c`.**
   - `voice_calls.py:668` (`start_huddle_turn`) sends `frames = {"sink": "backend", "endpoint": …}`.
   - The previous image, b7625bc, builds `CallFramePublisher(spec["endpoint"], spec.get("channel", ""), …)` (`turn.py:292` at b7625bc). With an empty channel, `FramePublisher.emit`/`_stream` return before publishing, so no frame ever reaches the worker.
   - The turn still runs and bills. `Turns.running()` holds the exchange open for `STALE_TURN_SECONDS` (120 s) with the tile on "Thinking…", then it goes quiet.
   - `hermes-version.json`'s note says "the prod dispatch and the roll follow". Verify `containerUri` per prod runtime with `aws bedrock-agentcore-control get-agent-runtime`, or run `roll_hermes_runtimes --all`.

2. **Important: no "joining" state, so a double click or two people during cold start dispatches two workers.**
   - Where: `routers/huddles.py:101-106`, `HuddleProvider.tsx:53-75`, `RoomHeader.tsx:155`.
   - `has_ceo` is false for the whole ~20 s cold start, so every `/join` in that window calls `create_dispatch` again. This includes a second click, because the button only disables once `huddle.roomId` is set, after connect and mic.
   - Two jobs then join as identity `agent-ceo`. LiveKit evicts the older one (duplicate identity), so its job shuts down. If someone had already summoned on it, that exchange ends mid-answer. Each extra job also pays for its own STT streams.
   - Fix: dedupe dispatch server-side (`list_dispatch` per room, or a short conditional row), and disable the button while `join` is pending.

3. **Important: hold-to-talk or tap-to-talk released before the summon returns is silently dropped.**
   - Where: `huddle_agent/huddle.py:170-173` (main), `:227` (PR).
   - `talk_end` only nudges when `self._x` exists, but `_x` is set at the very end of `summon` (backend summon, persona build with a `jev.agent_card` per teammate, then GPT-Live connect). That takes several seconds.
   - A user who presses, asks a short question and releases gets no nudge. The summon then completes with `request=None`, nothing replies, and the exchange idles out 20 s later. Their question is lost.
   - Probe: `A quick release -> nudged? False | exchange open: True`.
   - Fix: remember a pending `talk_end` per identity and nudge right after the summon installs `_x`.

4. **Important: pressing "Hold to talk" before Lightbulb has joined leaves the button "talking" for 7 s, then shows an error.**
   - Where: `HuddleBar.tsx:129-133`, `HuddleProvider.tsx:93-98`.
   - `performRpc` to a missing identity does **not throw**. `getRemoteParticipantClientProtocol` falls back to `CLIENT_PROTOCOL_DEFAULT` (`Room.ts:2575-2576`), a v1 `rpcRequest` packet goes to nobody, and the ack timer rejects with `CONNECTION_TIMEOUT` after `maxRoundTripLatencyMs = 7000` (`RpcClientManager.ts:65,90-97`).
   - The UI does recover: talking is reset and "Couldn't reach Lightbulb — try again." is shown. But the button sits pressed for 7 s, and a release in that window sends a second doomed `talk_end` that raises the same error again 7 s later.
   - Fix: disable the button (or say "Lightbulb is joining…") while `ceo` is absent.

5. **Important: after a GPT-Live session dies, the next `reply_to` raises and permanently kills that person's transcription.**
   - Where: `huddle.py:145-147` (main), plus PR `:150-163`. Call sites are `agent.py:168-170` and PR `:185-189`.
   - An unrecoverable realtime error closes the AgentSession (`agent_session.py:1988-2020`). After that `_activity` is None, and `generate_reply`/`interrupt` raise `RuntimeError("AgentSession isn't running")` (`:1599-1600`, `:1648-1649`).
   - Nothing in `start_live` listens for the session's `close` event, so the `_Exchange` keeps pointing at the dead session. It lingers up to 20 s, or up to 120 s while a turn is "running".
   - In that window, a non-speaker's wake-word line (and in the PR, a cut-in, a cutter's final or a hand-off return) calls `reply_to`. The exception propagates out of `await huddle.on_final_transcript(...)` inside `transcribe`, the `finally` closes that person's STT stream, and the task is never restarted.
   - `spawn()` discards the task, so the error is never logged either. From then on that person cannot summon Lightbulb for the rest of the room.
   - Probe: `C: on_final_transcript raised -> AgentSession isn't running`.
   - Fix: end the exchange on the session's `close` event, guard `reply_to`/`nudge` like the PR guards `interrupt`, and wrap the `transcribe` body so one bad event cannot end the loop.

6. **Important: when the worker crashes or never arrives, the room is stuck with no recovery, and billing claims stay held.**
   - Where: `HuddleBar.tsx:121-122`, `voice_calls.py:595`, `voice_calls.py:782`.
   - The client shows "Lightbulb is joining…" forever. There is no timeout, and there is no re-dispatch, because `/join` is the only dispatch path and the Go-live button is disabled for the room you are in.
   - The open huddle call row keeps the workspace's free claim (`until = now + budget + 180`) or credit hold until the sweeper reaches `deadline + 60 s`. Meanwhile every free 1:1 call in the workspace gets `voice_busy`.
   - The presence marker also sticks, because only the worker publishes `room.huddle.changed`.
   - Fix: client-side timeout with "Try again" (which re-POSTs `/join`), and a `has_ceo`-false re-dispatch when someone presses Talk.

7. **Important: a channel without the CEO in it gets a voice name GPT-Live may not accept (unverified against the live API).**
   - Where: `voice_calls.py:582-583`, `voice_persona.py:11-14`.
   - `voice_agent` falls back to `team[0]` when the CEO isn't a non-observe member, and `voice_for` then hashes into `("marin","cedar","alloy","ash","ballad","coral","echo","sage","shimmer","verse")`.
   - The plugin's `GPTLiveVoices` is `aster|beacon|cinder|marin|stone|vesper` (`gpt_live_model.py:74`). Only `marin` overlaps.
   - Huddles always speak as "Lightbulb" anyway, so pass a fixed GPT-Live voice for `kind == "huddle"`.
   - A new channel holding only, say, Engineering is the common case that hits this.

8. **Important: a delegation can send someone else's line as the question.**
   - Where: `huddle.py:228` (main), `:287` (PR).
   - A wake-word summon sends the request *typed* (`reply_to`), so GPT-Live's `pending_transcript` (its own audio speech buffer) is empty. The fallback is the last transcript line, which belongs to whoever spoke last, not the asker.
   - Example: A says "Lightbulb, what did we ship?", B says "good question" during the multi-second summon, and the delegated utterance becomes "B: good question". `voice_routing.pick` routes on the utterance.
   - Fix: keep the exchange's last typed request and prefer it.

9. **Important (cost): every participant is transcribed for the whole life of the room, unbilled and uncapped.**
   - Where: `agent.py:127,158-178`.
   - `openai.STT(use_realtime=True)` runs one stream per human for as long as they sit in the room, whether or not Lightbulb is summoned.
   - Only the `huddle.stt.seconds` metric is emitted. Nothing bills the workspace, and nothing ends an idle room: a forgotten tab keeps the job and STT running indefinitely.
   - Decide on a room idle cap and on whether STT time draws on voice minutes.

10. **Minor: the summon's transcript context is one append of up to 6,000 characters.**
    - Where: `huddle.py:208` (main), `:265` (PR).
    - The `Transcript` cap is 6,000 characters (~1,500 tokens), but each `append_thinking` is "capped at 500 tokens" (`gpt_live_model.py:1064-1066`). `frames.py` already chunks at 1,400 characters for this reason; this call doesn't.
    - If the server rejects instead of truncating, the plugin logs a recoverable error and the model starts with no context. Chunk it like `APPEND_CHARS`.

11. **Minor (latency and load): the backend frame relay costs more per batch than AppSync and also relays reasoning.**
    - Where: `turn.py` `_backend_publish`; relay route `huddles.py:178-187`.
    - Each batch of 5 deltas is a synchronous POST from the model's stream-callback thread (`FRAME_TIMEOUT_S = 5`). The backend then does two consistent DynamoDB reads (`get_call` plus `_require_hook_token`) and opens a new `LiveKitAPI` HTTP session for one `SendData`.
    - Reasoning deltas (`type: "thinking"`) are relayed too, even though the worker ignores them.
    - A long answer is dozens of these round trips, slowing the run's own streaming. Drop `thinking` for the backend sink, and consider a larger batch for it.

12. **Minor, collected:**
    - **Presence order.** `presence` POSTs run as concurrent `spawn`ed tasks (`agent.py:193-194`), so a join followed quickly by a leave can land out of order. The stale snapshot then sticks until the next change or a reconnect.
    - **Guests and other non-2xx seeds poll forever.** `useRoomHuddle.ts:43` retries every 30 s on any error, including the permanent 404 a shared-channel guest gets. `RoomHeader.tsx:76` still calls it for guest channels.
    - **Misleading error text.** `HuddleProvider.tsx:78-85` maps an `ApiProblem` body (`{code: "ROOM_NOT_FOUND"}`, uppercase) and a `NotFoundError` (no microphone) to `connection_lost`, which reads "The call dropped."
    - **Toggle stays pressed after a refused summon.** In tap mode, the button stays `aria-pressed` until the next tap. The RPC returned "ok" at once, and the refusal arrives as `huddle.error`.
    - **A late failure can cancel a newer press.** A `talk_start` rejection resets `talkingRef` even if the user has pressed again since (`HuddleProvider.tsx:95-96`).
    - **Second summon is dropped.** Two wake-word summons at once lose the second request entirely (`huddle.py:137`, `not self._lock.locked()`).
    - **Same user in two tabs.** One user in two tabs or devices evicts the first with "The call dropped." If that user was the speaker, the transient `participant_disconnected` ends the exchange (`huddle.py:119`).
    - **No StartAudio fallback.** If a browser blocks autoplay, `RoomAudioRenderer` stays silent and nothing tells the user. In practice an active mic capture usually unlocks it.

### PR #3543

13. **Important: anything two words long from a non-speaker cuts Lightbulb off and takes the floor.**
    - Where: PR `transcript.py:48-54`, `huddle.py:153-155,179-181`.
    - The probe shows `real_speech` true for "Thank you.", "you know", "I see" and "no no". "Thank you." is also the classic hallucination of Whisper-family STT on silence or noise.
    - GPT-Live only hears the speaker, so a side remark between two other people ends the answer to the speaker. The floor then moves to the person who made the remark.
    - Fix: require addressing (wake word or a halt word), or a longer minimum (for example 4+ content words), and drop "thank you"-style fillers.

14. **Important: after a cut-in, the cutter's request reaches GPT-Live twice, and the delegation may carry only a fragment.**
    - Where: PR `huddle.py:179-189,150-152`.
    - The interim cut calls `_repoint` → `RoomIO.set_participant(cutter)` while they are still mid-utterance. GPT-Live then hears the tail of that utterance as audio, and the final is also sent typed via `reply_to`.
    - Expect either two responses or delegations, where the second `/turns` supersedes the first after both start runs, or a delegation whose `pending_transcript` is just the audio tail. For example "tell me about billing" without its opening "wait actually": that tail is non-empty, so `huddle.py:287` uses it as the utterance instead of the full line.
    - Fix: on an interim cut, interrupt only and defer the repoint to the final, or don't `reply_to` when GPT-Live will hear the audio anyway.

15. **Important (Minor if names are rare words): `addressed_by_name` is case-insensitive.**
    - Where: PR `transcript.py:57-75`.
    - Common words that are also names trigger a hand-off: probe `"…Did you mark it done?"` → `Mark Li`, and `"Will that work for everyone?"` → `Will Chen`.
    - It also picks a name that is the object of the question, not the person addressed: "…want me to send it to Aden?" hands off to Aden.
    - During the 8 s hand-off, the original speaker's audio is not heard live. Only a real-speech final from them is relayed back, so a one-word "yes" is lost to `lines`.
    - Fix: match names case-sensitively, and only in vocative position (followed by a comma, or "…, Aden?").

16. **Important: the PR adds `reply_to` call sites that inherit finding 5.**
    - Where: PR `huddle.py:150-163`.
    - `_Live.interrupt` swallows `RuntimeError` (`agent.py:70-76`), but the very next statement, `reply_to`, does not. The cut, cutter-final and hand-off-return paths can all raise into `transcribe`.

17. **Minor (caveat, unverified against the live API): the "fast" interim cut may not be fast.**
    - In `plugins/openai/stt.py:870-890`, interim events come from `conversation.item.input_audio_transcription.delta`.
    - For OpenAI realtime transcription those deltas stream after the server-VAD segment is committed, at the end of the utterance, not during it. So the cut fires shortly before the final, not "about every 0.5 s" while the person is talking.
    - Measure this in prod before building on it.

## Flows traced

1. **Go live.**
   - `/join` runs `_room_team`, mints a 15-minute token (LiveKit refreshes it for connected participants), then `has_ceo`, then dispatch. In the client, `new Room()` connects, then `setMicrophoneEnabled(true)`.
   - If mic access is denied, the `NotAllowedError` propagates unchanged (`LocalParticipant.createTracks` rethrows, and `setTrackEnabled:575-583` stops the tracks). The client handles it with `mic_denied`, after `leave()` has disconnected the room.
   - While the permission prompt is open, the user is already in the LiveKit room: the marker shows them, but there is no bar yet and the button is still enabled (finding 2).
   - Lightbulb absent for 20 s holds up: "Lightbulb is joining…", the person tiles, and `RoomAudioRenderer` all render with no Lightbulb. When it joins, `CeoSpeaking` mounts `useIsSpeaking` with a real participant, attributes start as `{}` ("Following along"), then `lightbulb.status` arrives.

2. **Second person.**
   - The worker's `participant_connected`/`participant_disconnected` run `humans()`. The python rtc pops the participant before emitting (`rtc/room.py:764-768`), so the snapshot is correct.
   - `presence` then publishes `room.huddle.changed`, and `useRoomHuddle` replaces its state. The only weak points are the ordering (finding 12) and that this works only while the worker is present (finding 6).

3. **"Lightbulb, what did we ship?"**
   - The wake regex matches and `summon` starts as a task. `start_huddle_call` runs the gates, persona, free claim or hold, and the row, then `_prewake`.
   - `start_live` pins RoomIO to the speaker, then the transcript append (finding 10), then `reply_to`. GPT-Live client delegation follows: `on_delegation`, `/turns`, `_dispatch_turn` (18 s runtime timeout, so a cold workspace may still produce "Sorry, I couldn't reach the team" if the prewake hasn't landed).
   - The bridge `{sink: backend}` POSTs to `/internal/calls/{id}/frames`, the hook token is checked, `SendData` goes to `agent-ceo` (server-sent, so `participant is None`, verified at `rtc/room.py:138-145`), then `on_data`, `Turns`, and `append_commentary` produces speech.
   - It breaks at finding 1 (unrolled runtime), 7 (voice name) and 8 (wrong utterance).

4. **Hold-to-talk RPC.** See findings 3 and 4. The Python `register_rpc_method` accepts the sync lambda (`rtc/participant.py:742-743`), and it answers "ok" at once, so the 10 s response timeout is never the problem.

5. **Leave and unmount.**
   - `leave()` bumps the attempt counter, clears `roomRef` before `disconnect()` (so the Disconnected handler stays quiet), and calls `disconnect(stopTracks = true)` by default, which stops the mic.
   - The Bar unmounts, which unmounts `RoomAudioRenderer`. The provider's effect cleanup runs `leave` on unmount.
   - A `setMicrophoneEnabled` that resolves after leave throws on publish and stops its tracks (`LocalParticipant.ts:612-617`). Clean.

6. **Error paths.**
   - Refused summon: `huddle.error` goes to the asker, and `errorText` covers `voice_limit` reasons (see finding 12 for the toggle).
   - `/turns` 409 `turn_conflict` is dropped silently. Any other failure speaks an apology.
   - A worker crash is finding 6, and a GPT-Live death is finding 5.
   - A LiveKit disconnect runs `leave` and shows `connection_lost`. Archive and delete call `close_room`, and member removal calls `remove_participant`, both best-effort and never raising (`messaging.py:2109,2279,2329`).

7. **PR cut-in and hand-off.** Interim, then final, for the same cutter does not double-cut: `agent_state` is forced to listening and the speaker is re-pointed. The races are findings 14 and 15, false triggers are 13, and the exception exposure is 16.

## Web hooks verified (components-react 2.9.24)

- **`useIsSpeaking(p?)`** calls `useEnsureParticipant(p)` and throws with no participant and no ParticipantContext. Every call site now passes a defined participant: `PersonTile` maps real participants, and `CeoSpeaking` only renders when `ceo` exists.
- **`useParticipantAttributes({participant})`** uses `useMaybeParticipantContext` and never throws. It is only used with `ceo` anyway.
- **`useParticipants()`, `useTracks()` and `RoomAudioRenderer`** need a `RoomContext`, and `HuddleBar` provides it around `<Bar/>`. With no CEO present they return arrays with no agent entry.
- **`useMultibandTrackVolume(undefined | placeholder)`** checks `!track || !track.mediaStream`, then zeroes the bands. It is safe both before the agent publishes and after `aclose` unpublishes `roomio_audio`.
- **The agent's track** is published with `TrackSource.SOURCE_MICROPHONE` (`room_io/types.py:88-89`), so `useTracks([Track.Source.Microphone])` finds it.
