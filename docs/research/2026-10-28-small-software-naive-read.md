# Naïve (usenaive.ai), read first-hand (28 Oct 2026)

Sources, all fetched 2026-10-28: ycombinator.com/companies/naive; siliconangle.com 2026-08-06; runtimewire.com launch article; usenaive.ai (home, /pricing, /primitives/compute, /licenses, /skill.md); usenaive.ai/docs (quickstart, api/apps.md, cli/apps.md, capabilities/deployments.md, platform/pricing.md, llms.txt); github.com/usenaive repos via API; not-so-naive.vercel.app (single-source allegation). Tags: [P] primary, [S] secondary, [U] unverified.

## Who
- YC Spring 2025, San Francisco, 12 people; founders Sean Dorje (CEO) and Dennis Zax (CTO); formerly Relixir Inc. [P YC; S]. Tagline "Autonomous Company Infrastructure"; "an AI research lab building autonomous companies" [P].
- $28.5M Series A led by Nexus Venture Partners with YC, Zetta, Liquid 2, announced 2026-08-06; "more than 30,000 developer customers"; run-rate "in the low double-digit millions" [S SiliconANGLE].
- Built on Paperclip (MIT) and Hermes by Nous Research (MIT), both credited on usenaive.ai/licenses [P]. A 30 Mar 2026 anonymous post alleged the runtime was a Paperclip fork without attribution [U]; the licenses page now credits it. Lightbulb's own workspace runs on a Paperclip fork and Hermes, so Naïve is the closest structural comparable to the workspace.

## What it sells
- "Describe your business, or connect your existing one," and it deploys AI employees with identity (email, phone, domains, third-party accounts, cards/bank via Stripe Issuing, KYC/KYB and LLC formation with the owner completing checks) [P home; S].
- Two surfaces: **Managed Agents** (`vetta` CLI/SDK/API: agents with mandatory budgets, sessions, computers = disposable Linux sandboxes with optional browser, files, skills, identity, cron "deployments", webhooks, audit logs) and **Apps** (hosted sites) declared together in one `naive.config.ts` (`defineProject({ name, blueprint, template, apps, agents, removed })`) applied by `naive up` (idempotent reconcile; `--dry-run` first; nothing deleted unless listed under `removed`) [P skill.md].
- Coding agents are onboarded by a manifest at usenaive.ai/skill.md ("Drop this into Claude Code, Codex, or Cursor"); guardrails: never invent or echo keys, show checkout URLs and stop, confirm before `naive up` "since a crew is money" [P].

## Apps, exactly
- `vetta app create <name> --type fullstack|frontend_only`; `vetta app deploy <app-id> <dir>` uploads a directory (skips node_modules, .git, dist, .env*), build runs async, poll `vetta app deployments`; `vetta app secrets` (write-only values), `vetta app domains` (domain must already exist in the org), `vetta app permissions`; `naive up` creates/updates/deletes apps from the config and can adopt ones made by hand [P cli/apps.md].
- API: app `{id, name (DNS label, unique per org), type, status provisioning|active|error, url, mcp, error}`; `fullstack` = managed Postgres (connection string pushed into the app env), object storage (`/v1/apps/{id}/storage/…`), SQL at `POST /v1/apps/{id}/db/query` plus `/db/tables`, `/db/rest/{table}`, `/db/migrations`, optional MCP endpoint that mints a `VETTA_MCP_TOKEN` so agents with access to the app get its tools; `POST /v1/apps/{id}/deployments` with base64 files, status queued→building→ready|error; delete tears down "the hosting project" and the database [P api/apps.md]. Not documented: auth for app users, serverless functions, preview vs production, custom-domain registration (connect only) [U].
- Substrate: the app-dev-templates README says "no Vercel or Supabase account needed, Naive provisions and manages the infrastructure for you"; env vars sync "to the app's Vercel project"; fullstack templates get "a dedicated Supabase project" with URL and anon key injected [P README]. So the apps run on Vercel + Supabase under Naïve's accounts; the user does not own them.
- Templates: five Next.js starters (four frontend-only themes, one `fullstack/saas-dashboard` on Supabase) [P]; "blueprint artifacts" (agency, media) declare agents + apps + questions + schedules and are installed per org [P api/apps.md; GitHub usenaive/agency-blueprint MIT].
- Compute primitive page: "Ship a Next.js app to a real URL with Postgres, auth, and storage included"; sample log shows domain + SSL issue, region iad1; dashboard shows edge functions and cron [P marketing; auth/functions not in the API docs, U].

## Pricing
- Standard $20/month per organization with $20 credit; Pro $200 with $200; 7-day trial with $10 credit, card required; custom for volume. Metered: model tokens by completion window; computers $0.0504/vCPU-hr + $0.0162/GiB-hr while running, nothing paused; browser $0.10/hr + $0.01/action; web search $0.00166/call; email $0.0008/send; mobile device $0.03/min. Unmetered: MCP, SDK, CLI; app database calls; storage has no published rate; no per-seat fee [P pricing].

## Read for Lightbulb's engine
- Naïve is the nearest thing to "an engine CLI that spins up apps and agents" that exists, and it sits on the same open-source base as Lightbulb's workspace. Its CLI is agent-first (JSON, scoped keys, skill manifest, dry-run/apply), its config is declarative, and apps and agents are declared in one file.
- The differences that matter: the apps run on Naïve's Vercel and Supabase accounts (the customer never owns the infrastructure; Lightbulb's decision is customer-owned via Stripe Projects); no documented app-user auth, functions, preview/production split, versions or rollback; no notion of a room or team sharing (an app is org-level, access via org permissions); the agent loop is Naïve's hosted managed agent, not the user's own Claude Code.
- Worth copying as patterns: the single declarative project file with budgets, `up --dry-run` then `up`, write-only secrets, the MCP endpoint per app so agents get the app's tools, the skill manifest for coding-agent onboarding, idempotent create-by-name.
